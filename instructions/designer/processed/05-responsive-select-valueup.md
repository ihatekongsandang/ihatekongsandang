## 배경
디자이너 A·B·C가 시안 9개를 냈다(`design/v0.3-responsive/A1~C3/`). 이번 단계는 디자인팀 워크플로우의 "선정·보강"이다. 9개를 채점해 1위를 고르고, 다른 시안의 장점을 더해 보강안 1개를 만든다. 이어서 2·3위 요약과 함께 사용자에게 보일 자료를 만든다.

사용자 결정은 다음과 같다.
- U1~U5 권장안을 그대로 따른다. 배너는 모바일·태블릿에서 이동해도 되고 닫기는 없다. 소개는 접는다. 다크 모드는 넣지 않는다. "링크" 표기는 뺀다. 글꼴은 시스템 폰트를 쓴다.
- 카드 이미지는 실제 사진으로 바꾼다. 공공누리 → 언론 og:image 순서이고, 공인의 공적 활동 사진은 허용한다. 사진이 없거나 깨지면 새 대체 카드를 쓴다. 대체 카드가 필요한 게시물은 약 11건으로 예상한다.

## 임무
1. **재측정**: 9개 시안을 같은 도구, 같은 조건으로 다시 잰다.
   - 디자이너 B가 초반에 포트 9341 충돌로 다른 디자이너의 Chrome에 붙었을 가능성을 보고했다. 그래서 자체 측정값은 그대로 믿지 않는다.
   - 포트는 전용 포트를 쓴다. 측정 도구는 하나로 통일한다(새로 짜거나 기존 것 중 하나를 고른다).
2. **채점**: 브리프 평가표(탈락 조건 + 가중치 100점)로 9개를 모두 채점한다. 근거는 측정값과 스크린샷 위치로 남긴다.
3. **보강안**: 1위를 바탕으로 다른 시안의 장점을 더한 최종안 1개를 `design/v0.3-responsive/final/`에 만든다. 형식은 정적 HTML이고 360·768·1024·1280 스크린샷과 토큰 표를 낸다.
   - 사진 카드와 출처 표시를 넣는다. 표시 형식은 card-image-policy를 따른다.
   - 새 대체 카드를 넣는다.
   - 홈·상세(ko/en)·태그·소개를 포함한다.
4. **사용자 결정 정리**: 9개 시안의 notes에 흩어진 결정 후보를 모으고 중복을 정리한다. 꼭 필요한 것만 번호 선택지, 장단점, 권장안으로 쓴다. 예: 배너 "스크롤 시 숨김"이 "닫기 없음"과 맞는지, "더 보기"를 "다음 페이지"로 바꿀지, 영어 부제 위치.
5. **사용자 비교 자료**: `design/v0.3-responsive/compare.md`를 만든다. 보강안과 2·3위를 같은 폭 스크린샷으로 나란히 두고, 차이를 3줄씩 요약한다. 사용자는 휴대폰으로 본다. 그러니 360 화면을 먼저 둔다.
6. **구현 범위 표**: 보강안 기준으로 바꿀 컴포넌트·파일, 난이도, 새 라우트 필요 여부(영어 월별 탐색 등)를 표로 만든다. 카드 이미지 코드 변경(card-image-policy P1~P12)과 겹치는 부분도 표시한다.
