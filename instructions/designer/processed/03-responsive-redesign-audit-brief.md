## 임무
1. **현황 실측**: 배포 사이트 https://ihatekongsandang.vercel.app 를 헤드리스 Chrome으로 찍는다(`docs/tools/programmer-04/cdp.mjs` 재사용 가능, 빌드·`next start` 금지).
   - 폭: 360·390(모바일), 768·834·1024(태블릿 세로·가로), 1280·1440(데스크톱)
   - 페이지: 홈 피드, 태그 페이지, 게시물 상세 ko/en, 소개, 약관
   - 스크린샷은 `docs/tools/designer-03/screens/`에 저장한다.
2. **사용자 친화성 진단**: 폭별로 문제를 찾는다. 근거는 스크린샷과 코드 위치로 남긴다.
   - 대상: 가독성(글자 크기·줄 길이·행간), 카드 밀도·열 수, 터치 영역, 내비·태그 탐색, 상세 읽기 흐름, 공유 버튼 위치, 여백, 태블릿 폭의 빈 공간·늘어짐, 다크 모드, 접근성 대비, 로딩·이미지 비율
   - 심각도(상·중·하)로 표를 만든다.
3. **디자인 브리프**: 디자이너 3명이 서로 다른 방향으로 시안을 만들 수 있게 쓴다.
   - 공통 제약: 담백한 톤, D6 자칭 금지, 기존 기능 유지(공유·갱신 표시·약관·영어), 새 의존성 없음(Tailwind 안), WCAG AA, 브레이크포인트 정의
   - 디자이너 A·B·C에게 줄 방향 3개를 서로 겹치지 않게 정한다(예: 읽기 중심 / 탐색 중심 / 카드 그리드 중심). 각 방향에 시안 3개씩 변주할 축을 적는다.
   - 시안 산출 형식: 정적 HTML 목업, 360·768·1280 세 폭 스크린샷, 토큰 표
4. **평가 기준표**: 다음 단계에서 9개 시안을 고를 채점 기준을 만든다(가중치 포함).
