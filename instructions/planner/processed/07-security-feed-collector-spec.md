## 배경 (사용자 지시, 2026-10-12)
안보 관련 게시 소재 **후보**를 공개 출처에서 주기적으로 자동 수집해 슈퍼바이저가 검토할 **후보 대기열**을 만든다.
⚠️ **소재 발굴 도구이지 자동 게시 도구가 아니다.** 후보가 게시물이 되려면 기존 절차(허용 출처 확인 → 초안 → 리뷰어 게이트/사용자 승인 → 게시)를 그대로 거친다. 수집기는 `content/`·`public/`에 아무것도 쓰지 않는다.

## 임무 — 기획서 `planning/security-feed-collector.md` 작성 (아래 9개 항목 전부 확정)

### 1. 수집 출처 목록 (표)
후보 출처를 **하나씩 실제로 접속해** 확인한다(curl·WebFetch 등. 확인 일시를 출처마다 기록).
| 구분 | 후보 |
|---|---|
| 한국 정부 | 합동참모본부, 국방부, 통일부, 국가정보원 보도자료 |
| 미국 | 미 국방부(DoD), 주한미군(USFK) |
| 통신사·언론 | 연합뉴스 북한 섹션 등 PRD §6① 허용 언론사에 해당하는 매체 |
| 전문 매체 | 38 North, NK News, RFA |
| 북한 관영 | KCNA는 국내 직접 접속 차단 → KCNA Watch 같은 공개 아카이브를 쓸지 판단. 쓴다면 "북한 측 주장" 표기 규칙도 함께 정함 |

출처마다 다음 열을 채운다: **① 공식 RSS/공개 API 제공 여부(실제 URL·응답 확인)** · **② 이용약관·robots.txt상 자동 수집 허용 여부(해당 조항·경로 인용)** · **③ 수집 주기** · ④ 국내 접속 가능 여부 · ⑤ 유료벽 여부 · ⑥ 확인 일시. 확인 못 한 칸은 "확인 필요".

🔴 **반드시 판단할 정책 쟁점** — PRD §6①의 허용 출처는 "등록 언론사·수사기관(검찰·경찰·국정원 등) 공식 발표·법원 판결문"이다. 따라서:
- 국방부·합참·통일부 보도자료, 미 국방부·주한미군 발표, 해외 전문 매체(38 North·NK News·RFA), 북한 관영 매체가 각각 **(가) 게시물 `sources[]`에 쓸 수 있는 근거**인지, **(나) 소재 발굴 단서로만 쓰고 게시하려면 허용 출처를 따로 찾아야 하는지**를 출처별로 분류한다.
- (가)로 넣으려면 PRD §6① 개정이 필요한 출처는 "**사용자 결정 필요**"로 따로 모아 개정안 문구와 근거를 제시한다(기획자가 임의로 확정하지 않는다).

### 2. 수집 방식
RSS·공개 API 우선, HTML 스크래핑은 약관·robots 허용이 확인된 경우에만, 약관이 금지하는 출처는 제외. **요청 간격(초)·출처별/전체 하루 호출 상한**, User-Agent 표기 방침, 실패·차단 시 재시도/백오프 규칙을 숫자로 정한다.

### 3. 선별 기준 — 명시적 규칙으로 (AI 판단에 맡기지 않는다)
- 키워드 사전: 예시(미사일, 핵, 도발, NLL, DMZ, 간첩, 국가보안법, 사이버공격, 무인기 등)를 출발점으로 한국어·영어 표기, 동의어·제외어(오탐 방지 예: 스포츠 "도발", 게임 "미사일")까지 표로 확정.
- 매칭 범위(제목만 / 제목+피드 요약), 대소문자·띄어쓰기 처리.
- **중복 제거 규칙**: URL 정규화(쿼리·추적 파라미터 제거 등), 같은 사안의 다매체 보도 묶음 기준(제목 유사도 등 계산 가능한 규칙으로).
- **우선순위 규칙**: 점수식으로 정의(예: 출처 등급 × 키워드 가중치 × 최신성). 기존 게시물과 이미 다룬 사안 표시 방법 포함.

### 4. 후보 1건의 데이터 형식
필드는 **제목, 출처명, 원문 URL, 발행 시각, 매칭된 키워드, 수집 시각**만(+ 중복 묶음·우선순위 계산에 꼭 필요한 파생값이 있으면 근거와 함께 최소한으로). **원문 전문·본문 발췌는 저장하지 않는다**(저작권, PRD §5.1). 파일 형식(JSONL 등)·스키마 예시 1건 포함.

### 5. AI 요약을 쓸 경우의 규칙 (쓸지 말지부터 결정)
쓰는 경우: 원문에 없는 내용 추가 금지 · 원문 URL이 없거나 열리지 않는 항목은 후보에서 제외 · 요약에 "확인된 사실"과 "주장·전망"을 구분 표기 · 북한 관영 매체 내용은 "북한 측 주장"으로만 · 요약을 저장하는지(저장 시 저작권·날조 검증 방법) · 사용할 모델과 근거. 쓰지 않는 경우 그 근거.

### 6. 저장 위치
배포 대상(`content/`·`public/`) 밖. **공개 레포 커밋 vs 로컬 전용(.gitignore)** 을 근거와 함께 결정(공개 레포라 편집 대기열이 공개되는 점, 저장 용량, 업로더·슈퍼바이저가 같은 작업 폴더를 쓰는 점을 고려). 보존 기간·정리 규칙 포함.

### 7. 실행 환경
로컬 예약 실행(cron 또는 launchd) 기준. **가벼운 단일 스크립트 구조**(런타임·의존성 최소, 메모리 사용 목표치). 절대경로·개인 정보(전화번호·계정)는 코드에 넣지 않고 **환경변수로만** 받는다. 실행 로그 위치, 실패 알림 필요 여부(필요하면 방식만, 개인 연락처는 환경변수).

### 8. 슈퍼바이저 사용 흐름
- 사용자가 "안보 소재 뭐 있어?"라고 물으면 슈퍼바이저가 대기열을 읽고 보고하는 절차(몇 건·어떤 순서·보고 양식).
- 후보 → 게시 초안으로 넘기는 절차: 담당 세션(반공-업로더가 URL 게시 전담 — 역할 분담 문서 참조), 허용 출처 재확인, PRD §6②③ 적용 지점, 후보 상태값(신규/검토중/게시/보류/제외)과 갱신 주체.

### 9. 비용·리소스 사전 추정
하루 호출 수(출처별 합계), AI 요약을 쓸 경우 하루 토큰 사용량·월 비용 추정. **계산식과 가정을 명시**한다(가정은 가정이라고 표기).
