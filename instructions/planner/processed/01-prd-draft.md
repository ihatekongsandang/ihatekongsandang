## 임무 — PRD v0.1 초안 작성

### 서비스 정의 (사용자 원문)
> "내가 슈퍼바이저에게 URL이나 사진, 사진&글을 주면 그게 게시되는, 카드 형태 뉴스 소식지 정도의 사이트. 모바일, 웹 모두 지원."

### 사용자 확정 사항 (변경 불가 — 그대로 반영)
| 항목 | 결정 |
|---|---|
| 게시 파이프라인 | 파일 기반. 슈퍼바이저가 `content/posts/*.md`(+이미지) 작성 → 커밋·푸시 → Vercel 자동 배포. DB·로그인·관리자 화면 없음 |
| 게시물 유형 3종 | ① URL(링크 카드 — OG 제목·썸네일·요약 자동 추출) ② 사진 ③ 사진+글 |
| v0.1 | 열람 전용 프로토타입 (로그인·댓글·구독·반응 없음) |
| 로드맵 순서 | v0.1 프로토타입 → v0.2 디자인 수정 → v0.3 **제보받기** → v0.4 좋아요/싫어요 → v0.5 공유 + 공유수 표시 → v0.6 댓글 |
| 디바이스 | 모바일 + 데스크톱 모두 지원 (대응 방식 — 반응형/적응형 — 은 PRD에서 근거와 함께 **제안**, 사용자 확정) |
| 슬러그 | `ihatekongsandang`. 한글 서비스명·브랜드 톤은 **미정** — 추측 금지, "사용자 결정 필요" 항목으로 후보 없이 비워둘 것 |

### PRD 포함 항목
1. **최상위 원칙** — 유저 확보 최우선 / 방향 > 속도 / 5대 핵심 축 / 정확성 우선
2. **의사결정 트래커** — 확정(위 표)·미결(서비스명·도메인·카테고리·디바이스 대응 방식 등) 표
3. **타깃 사용자·핵심 가치 가설** — 누가 왜 이 카드 소식지를 보는가. ⚠️ 서비스 주제·성격은 슬러그 외에 주어진 정보가 없다. **주제를 추측해 서술하지 말고** "사용자 확인 필요" 질문 목록으로 정리할 것 (예: 다루는 소재 범위, 톤, 익명/실명 운영 여부)
4. **게시물 모델(콘텐츠 스키마 요구사항)** — 3종 유형 공통 필드(안정 ID/슬러그·제목·게시일·카테고리·태그·출처)와 유형별 필드. 🔴 **안정 ID는 v0.4~v0.6(반응·공유수·댓글)의 키가 되므로 변경 불가 원칙 명시**. 슈퍼바이저가 손으로 작성하기 쉬운 형식(frontmatter) 요구사항으로 서술 — 구체 스키마 확정은 프로그래머 몫
5. **정보구조(IA)·핵심 화면** — 홈(카드 피드), 카테고리/태그, 게시물 상세, 소개/출처 정책 페이지. 무한스크롤 vs 페이지네이션 등은 근거와 함께 제안
6. **URL 카드 인용·저작권 정책** — OG 메타 인용 범위, 원문 전재 금지, 출처 링크 필수, 이미지 저작권(사진 게시물은 사용자 소유/허가 전제) 정책. 제보(v0.3) 시 제보자 저작권 동의 골조도 사전 설계
7. **후속 사이클 사전 설계(골조만)** — v0.3 제보(입력 항목·스팸 방지·슈퍼바이저 검수 흐름·알림), v0.4 좋아요/싫어요(익명 1인 1표 방식 후보), v0.5 공유(공유 수단·공유수 집계 정의), v0.6 댓글(익명/로그인 여부 — 미결로 표기). 각 사이클이 v0.1 스키마에 요구하는 것만 명시
8. **5대 핵심 축별 적용 방안** — SEO(카드별 메타·OG·sitemap·JSON-LD)·AI 검색·접근성(WCAG 2.2 AA)·보안(외부 링크 rel·CSP)·UX
9. **v0.1 KPI** — 유입·재방문·카드 클릭률 등 (측정 도구는 제안)
10. **로드맵** — 위 6단계 순서 그대로, 단계별 완료 정의(DoD)
