# 업로더 27 — 인물 없는 자료사진(A-2) 묶음 2 (20건 목표)

담당: 반공-업로더 · 빌드 없음(validate만) · 커밋 금지(슈퍼바이저가 리뷰 후 커밋)

## 배경
- 사용자가 2026-11-11에 "이미지 아직도 적어"라고 했다. 대표 이미지가 있는 게시물은 41/209건이다.
- 시범(업로더 26·26-1, 리뷰 69, 커밋 a339b3b)의 절차와 결과를 그대로 이어서 쓴다.
- 🔴 출처 한정은 시범과 같다(슈퍼바이저 판단). CC BY 2.0/3.0/4.0(버전 명시), CC0 1.0, 이용조건이 CC BY 4.0인 기증만 쓴다.
- 퍼블릭 도메인, CC BY-SA, 공공누리 제1유형은 아직 쓰지 않는다. 표시 코드나 사용자 결정이 남아 있기 때문이다. 대신 찾은 것은 "참고 후보"로 id·URL·라이선스만 적는다. 다음 묶음 규모를 정하는 데 쓴다.

## 할 일
1. **대상**: 이미지가 없는 게시물에서 고른다. 이번 묶음에서는 최근 게시물(11월 게시분)을 먼저 본다. 피드 첫 화면에 보이는 게시물이기 때문이다.
   - 장소·기관 예:
     - 대통령실(용산) 청사 — 대통령 발언·정책 게시물
     - 국회의사당 — 같은 연작의 미사용 후보를 써서 분산한다
     - 대법원·헌법재판소
     - 정부청사
     - 판문점·DMZ·통일전망대
     - 중국 대사관 등 외국 공관 건물(외교 게시물)
     - 국방부·합참 청사
   - 고르지 않는 게시물: 의혹 대상이 그 기관 자체인 게시물, 제목이 비난형이라 결합 위험이 있는 게시물(정책 §4.5).
2. **검색처**:
   - 서울연구데이터서비스(시범 출처)
   - 위키미디어 공용: 파일 페이지의 라이선스 틀에서 CC BY 2.0/3.0/4.0과 CC0만 쓴다. Flickr 등에서 옮겨 온 파일은 원 출처의 라이선스 검증 표시(리뷰 틀)를 확인하고, 검증 표시가 없으면 쓰지 않는다.
   - 공유마당(버전을 글자로 명시한 것만)
3. 사진 확인, 저장, EXIF, frontmatter, caption은 시범과 같다. 같은 원본은 3건까지만 쓴다(시범 사용분 A 3·B 3 포함해 계산).
4. **검증**: `npm run validate:content`에서 R=0이어야 하고 해당 id에 새 경고가 0이어야 한다. `git status --short` 전체를 적는다.
5. **기록**: 실패 사유를 검색처별로 적는다. 참고 후보(PD·BY-SA·공공누리)는 게시물별로 몇 건이 있었는지 적는다.
