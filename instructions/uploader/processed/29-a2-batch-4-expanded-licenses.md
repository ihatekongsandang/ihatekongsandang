- 후보 목록 `docs/qa/uploader-28-candidates.md`

## 1단계 할 일 (지금)
1. **대상 순서**: 국회·법조가 **아닌** 대상부터 본다. 청와대, 정부청사, 광화문, 판문점·DMZ, 통일전망대, 외국 공관, 장비(지뢰·미사일·드론·함정·항공기 기종을 지목한 게시물) 순이다. 국회·법조 게시물은 마지막에 본다.
2. **후보 확인**: 28 후보 목록의 파일과 새로 찾은 파일을 하나씩 직접 연다.
   - 사람이 없거나 점 크기(1% 미만)인지 본다.
   - 공사 중이거나 옛 모습이 아닌지 본다.
   - 워터마크가 없는지 본다.
   - 짧은 변이 400px 이상인지 본다.
   - 대상이 일치하는지 본다(3a는 범위 3단계, 3b는 개체 식별 표지가 없어야 하고 제목이 특정 사건 장면이면 불가).
   - 기관 의혹 판단(§4.5-5)을 적용한다.
3. **라이선스 확인**:
   - 버전은 글자로 확인한다.
   - PD는 `pdBasis` 근거를 원 페이지에서 직접 확인한다. us-gov는 원 기관 페이지에서 직무 촬영인지 확인한다. 제3자 크레딧이 있거나 군 표장이 주된 피사체이면 불가다.
   - Flickr에서 옮긴 파일은 검증 틀이 있어야 한다.
4. **준비물**: 저장소 밖 작업 공간에 원본, 리사이즈본, EXIF를 정리한 파일을 만든다. 게시물별로 frontmatter 초안(ko·en, license·`pdBasis`·caption 등)을 작성한다. 같은 원본 사용 수(6건 상한)와 publishedAt 인접(5건 이내 불가)을 미리 계산한다.
5. **1단계 보고**: 게시물별 채택·불가 표와 예상 건수를 트리거에 적고 반공-슈퍼바이저에 알린다. 그다음 2단계 신호를 기다린다.

## 2단계 할 일 (신호 뒤)
- frontmatter와 `public/images/{id}/`에 반영한다.
- `npm run validate:content`를 돌린다. R=0이어야 하고 대상 id의 새 경고가 0이어야 한다.
- `git status --short` 전체를 적는다.

## 🔴 금지
- git 쓰기, 빌드, `src/` 수정 금지. 사람이 나오는 사진 금지.
- 1단계에서는 `content/`·`public/`을 수정하지 않는다. 프로그래머가 같은 폴더에서 빌드 중이다.
- 트리거·오더·히스토리에 사진 저작자 이름, 실명, 옛 id, 다른 서비스명, 계정, 홈 경로를 쓰지 않는다.
- `gotdemcatch`·`attendkdz`·`wendmag` 파일은 건드리지 않는다.
