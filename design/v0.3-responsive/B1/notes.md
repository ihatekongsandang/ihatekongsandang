# B1 notes — 가로 스크롤 칩 레일 · 한 줄 압축 헤더 · 번호형 페이지 이동

> 디자이너 B · md오더 04-B · 방향 B(탐색 중심). 목업: `mockup.html`(정적, 외부 요청 없음). 스크린샷은 헤드리스 Chrome으로 `file://` 목업을 열어 실측했다(`docs/tools/designer-04-B/shoot.mjs`). 측정 원자료 `docs/tools/designer-04-B/measure-output.json`.

## 1. 방향과 변주 축 선택
- 태그 탐색 = B1 레일 / 헤더 = B1 한 줄 압축 / 페이지 이동 = B1 번호형
- 헤더: 한 줄 56px(로고 + 홈·소개·English). ko·en 모두 한 줄
- 태그 탐색: 가로 스크롤 칩 레일(칩 44px, 오른쪽 끝 페이드, 마지막은 "전체 주제 325개" 칩)
- 페이지 이동: 번호형(이전 1 2 3 … 18 다음, 44px)
- 열 수(base/sm/md/lg/xl): 1 / 1 / 2 / 3 / 3
- 카드 면: 테두리형(#8a8a94 1px, 3.4:1)
- 배너 자리: 모바일·태블릿(<1024) 하단 전폭 띠 48px(2줄), 본문 여백 60px 확보 / lg 이상 현행 세로 탭 유지
- 사진 출처 표시 자리: 사진 위 왼쪽 아래 검은 칩("사진: 대통령실", 흰 글자 17.7:1)
- 새 대체 카드(회색+빨간 줄 카드 대체): 아이콘 + "대표 이미지 없음"(연회색 면, 카드 테두리 3.4:1)
- 영어: 영어: 태그 링크 없음(C7). 월별 칩 레일(Nov 2026 … Jul 2026, 건수) — **새 라우트 필요, 구현 범위 확인 필요**. 헤더 한 줄 57px. 확정 표기 "공산당이싫어요 (Korea Politics & Security Brief)"는 헤더에서 로고만 쓰고 전체 표기는 h1에 그대로 둔다.
- 상세 순서: 제목 → 요약 → [원문 기사로 이동] → 메타 → 안내 상자 → 공유 → 원문 미리보기(사진 출처 칩) → 본문 → 배경 보도 → 태그 → 같은 태그 글 3건 → 이전/다음 글 → 정정 안내.
- 사용자 결정 반영: U1=a(배너 자리·크기 변경, 닫기 없음 유지) · U2=a(다크 미도입, 토큰 표에 값만) · U3=a(홈 소개 D1 확정문 모바일 한 줄 + "더보기", 문구 그대로, `<details>`) · U4=a(카드·상세의 "링크" 유형 표기 삭제) · U5=a(시스템 폰트).

## 5. 장단점
- 장점: 레일은 구현이 가장 작다(기존 TagNav를 flex-wrap → 가로 스크롤로). 번호형은 18페이지 건너뛰기에 직관적.
- 단점: 칩 14개 이후는 레일을 끝까지 밀거나 "전체 주제"로 가야 한다. 360에서 번호 5개 + 이전/다음이 꽉 찬다(320에서는 줄바꿈).

## 6. 사용자 결정 필요
- 영어 월별 탐색: 새 라우트 필요 → 구현 범위 확인 필요(없으면 영어는 시간순만).
- 영어 사이트명 확정 표기를 헤더와 h1로 나누는 배치(헤더는 로고만, 전체 표기는 h1)— B1·B2·B3 공통.
- 상세 끝 "이전/다음 글"·"같은 태그 글": 기존 태그·날짜로 만들 수 있어 새 데이터는 없다. 도입 여부 확인.
- 사진 출처 문구("사진: {기관·언론사}")는 콘텐츠 스키마에 출처 필드가 필요하다 → 기획·프로그래머 확인 필요.
- 새 대체 카드는 지금의 회색+빨간 줄 카드를 대체한다. 첫 태그·출처명을 쓰는 안이 있으면 스키마에서 값을 가져와야 한다.
- 카드 아래 "링크" 삭제 외에 상세 배지 "링크"도 삭제했다(U4 확장 해석 — 확인 필요).
- 상세 미리보기 라벨(U6)은 현행 문구 유지.
- 배너 하단 띠·sticky 줄은 U1=a 범위 안이지만 레이아웃이 현행과 크게 다르다 — 선정 시 재확인.
