## 1. 용어 확정 — "주제" 한 낱말 (리뷰 31 P3-5, 결정 14-7)

**결정**: 사용자 화면에 나가는 낱말은 **"주제"로 통일**한다. 근거: 레일 이름·끝 칩("전체 주제 N개")·태그 화면 건수 문장("이 주제로 정리한 게시물 N건")이 이미 "주제"이고, 일반 방문자에게 "태그"는 해시태그 느낌이 강해 뉴스 큐레이션의 분류 개념에 맞지 않는다. 리뷰어 권고와 같다. 사용자 결정은 필요 없다(리뷰 31 §9).

**유지하는 것**: URL `/tag/…`·`/tags`, frontmatter 키 `tags`, 코드 식별자(`getAllTags` 등), 사이트맵 경로. 작성자용 문서(`content/README.md`, guide)는 필드 이름이 `tags`이므로 "태그(`tags`)"로 써도 된다 — **화면(방문자가 보는 문구·메타)만** 통일한다.
**표기**: 태그 한 개의 이름은 `#dmz`처럼 해시를 붙인 현행 표기를 유지한다(태그 피드 h1 "#dmz").

| 위치(현행 문구) | 바꿀 문구 |
|---|---|
| `src/lib/i18n.ts` 상세 보조 열 이름 `tags: '태그'` | `'주제'` |
| `src/lib/i18n.ts` 영어 `tags: 'Tags'` | `'Topics'`(레일 이름 `Topics`와 같게) |
| `src/app/(ko)/tags/page.tsx` `TITLE = '전체 태그'` | `'전체 주제'` (h1·`<title>`·메타) |
| 같은 파일 `aria-label="태그 목록"` | `"주제 목록"` |
| 같은 파일 빈 상태 "아직 태그가 없습니다." | "아직 주제가 없습니다." |
| `src/app/(ko)/tag/[slug]/page.tsx`의 설명 "`'${tag}' 태그로 묶인 게시물입니다.`" | "`'${tag}' 주제로 묶인 게시물입니다.`" |
| `src/app/(ko)/tag/[slug]/page/[page]/page.tsx`의 "`'${tag}' 태그로 묶인 게시물입니다.`"·"`'${tag}' 태그 게시물 N페이지`"(메타·JSON-LD 2곳) | "`… 주제로 묶인 …`"·"`… 주제 게시물 N페이지`" |
| `src/app/llms.txt/route.ts` `'## 태그'` | `'## 주제'` |

- 영어 사이트에는 태그 목록 화면이 없다(`TagNav`는 ko만). 영어 상세 보조 열의 `Tags`만 `Topics`로 바꾼다.
- SEO 영향: `/tags`의 `<title>`·h1 문구가 바뀐다. URL·사이트맵·내부 링크는 그대로라 리다이렉트는 필요 없다. 문구 교체 직후 검색 색인에서 제목이 갱신되기까지 시간이 걸린다(영향은 작다).
- 코드 항목: **C3**(§3).

### 2.2 소개 페이지 "인용·저작권" 절 대체 문구 (정책 P12, 디자인 "기획 확인으로 넘기는 것")
현행 문장 2개를 아래로 바꾼다. 현행: "원문 썸네일은 원 사이트의 이미지를 그대로 참조(핫링크)하며 이 사이트에 복제해 두지 않습니다."와 "공유 미리보기 이미지에는 원문 썸네일을 쓰지 않고 이 사이트의 자체 이미지를 씁니다. **인물의 얼굴이 식별되는 원문 썸네일은 사용하지 않고 대체 이미지로 표시합니다.**" — 마지막 문장이 사진 결정과 충돌한다.

**확정 문안(ko, 목록 항목 4개) — 🆕 16 재정정본(사용자 결정 Q2=b 반영, 15-1 정정본을 대체)**

> 🆕 16-1: 2번은 리뷰 34 §2.4 정정 문안을 글자 그대로 옮겼다(P2-2). 영어 문안("Quotes, images and copyright", P2-3)은 `planning/q1-redirect-q2-sns-image-plan.md` §2.2 en.

> 사실 근거(기획자 16이 `content/posts/` 207건 전수를 다시 셈): SNS 원 게시물의 이미지를 `public/images/{id}/`에 **저장해 쓰는 `self` 게시물은 139건**이다(리뷰 32의 140건에서 1건 줄었다 — caption이 "원문 …"으로 시작하나 사이트가 직접 만든 요약 이미지 1건을 뺐다). 나머지 68건은 이 사이트가 만든 이미지(자체 제작 텍스트 카드 67 + 요약 이미지 1)다. 사용자 결정 Q2=b로 저장본을 단계적으로 정리하므로 문안은 "정리하기로 했으며"로 쓴다(C4 배포 시점에 교체 0건일 수 있어 현재진행형을 피했다). 사용자 결정 Q3=a: 언론 이미지로 못 바꾸는 저장본은 대체 카드로 내린다. 집계·시험·정리 계획은 `planning/q1-redirect-q2-sns-image-plan.md` §2·§3.

1. 외부 글은 **본문을 전재하지 않습니다.** 원문의 메타 정보(제목·요약)만 인용하고 원문 링크를 함께 제공합니다.
2. 카드의 대표 이미지는 글에 따라 다릅니다.
   - **언론 기사의 사진을 쓰는 글**은 그 사진을 이 사이트에 복제해 두지 않고 원 매체 주소에서 그대로 불러와 보여 줍니다. 사진 아래에 출처(사진 권리자 또는 매체)와 원문 링크를 적습니다.
   - **SNS 게시물을 다룬 글 중 상당수**는 원 게시물의 이미지(썸네일)를 이 사이트에 **저장해** 보여 줍니다. 이 이미지는 원 게시물에서 가져온 것이고, 권리는 원 게시자 또는 이미지의 권리자에게 있습니다. 이 방식은 **정리하기로 했으며**, 근거 언론 기사의 사진 또는 대체 이미지로 차례로 바꿉니다.
   - 일부 글은 이 사이트가 게시물 요지를 정리해 만든 카드 이미지를 씁니다. 이 이미지도 차례로 바꿉니다.
   - 공공누리로 개방된 공공 사진을 쓸 때는 사진 아래에 공공누리 유형을 적습니다(현재 쓰는 사진은 없습니다).
   - 사진이 없거나 불러오지 못하면 대체 이미지를 보여 줍니다.
3. **언론 기사 사진과 공공 사진에 나오는 인물**은 **정치인 등 공인의 공적 활동**(국회·정부 일정, 기자회견, 외교 행사 등)에 한합니다. 공식 일정 사진에는 공무를 수행 중인 수행원·통역·배석자가 함께 나올 수 있습니다. 일반 시민·미성년자·사건 피해자·부상자 등 공인이 아닌 사람이 알아볼 수 있게 나온 사진은 쓰지 않습니다. 사진은 게시물이 다루는 사건과 같은 사건 당시의 것만 쓰며, 사진은 게시물 내용의 근거가 아닙니다. 의혹·수사·재판을 다룬 게시물의 사진에는 누가·언제·어디서 찍은 것인지 사진 설명을 붙입니다.
4. 공유 미리보기 이미지에는 이 사이트의 자체 이미지를 씁니다.

- **현행 문장의 정정 대응**: 현행 "원문 썸네일은 원 사이트의 이미지를 그대로 참조(핫링크)하며 이 사이트에 복제해 두지 않습니다."는 SNS 저장본(139건)과 이미 맞지 않는다(리뷰 32 §9). 위 2번이 이를 대체한다. 현행 "인물의 얼굴이 식별되는 원문 썸네일은 사용하지 않고 대체 이미지로 표시합니다."는 공인 얼굴 B 사진 첫 배포와 동시에 거짓이 되므로 지운다 — **그래서 C4는 공인 얼굴 사진 첫 묶음 배포보다 먼저 나가야 한다**(§3.4).
- ⚠️ 이 문안은 **SNS 저장 이미지(139건)의 얼굴 기준을 말하지 않는다.** 현행 "얼굴이 식별되는 … 사용하지 않는다" 문장을 지우면 그 139건에 대한 약속도 함께 사라진다. 139건이 실제로 얼굴 식별 이미지를 쓰지 않는지는 확인하지 않았다 — **정리 묶음의 단계 0에서 담당자가 이미지를 직접 보고 확인**한다(`planning/q1-redirect-q2-sns-image-plan.md` §3.4).
- 🆕 16: **정리가 끝나 저장본이 0건이 되면 2번의 SNS 줄을 지운다**(슈퍼바이저가 C4 후속 오더). **영어 소개 페이지에는 이 절이 없다.** 같은 사실을 영어 독자에게도 알리는 영어 "Quotes, images and copyright" 절(문안은 위 계획 문서 §2.2 — 🆕 16-1: 리뷰 34 §2.4 문안, 절 제목 "Quotes, images and copyright")을 추가할지는 슈퍼바이저 결정이다(기획자 권고: 추가).
- "정정·삭제 요청" 절의 "원문 이미지 사용 중단" 문구는 그대로 둔다(사진 사용 중단 요청을 이미 포함).
- 코드 항목: **C4**(§3).

### 2.4 `content/README.md` 갱신 문안 (정책 P12 — 프로그래머 13의 초안을 정책 확정본에 맞춰 다듬은 것)
> 반영은 프로그래머(또는 슈퍼바이저)가 한다. 이번 오더에서는 README를 수정하지 않았다.

**§3.1 표 `image` 행 교체**
| `image` | | `{kind, src, alt, caption, creditName, creditNameEn, sourcePageUrl, license, retrievedAt, faceNote}` | 카드 대표 이미지. `kind`를 생략하면 `self`(운영자 제작 이미지). 공공누리·언론 기사 사진은 §3.6 |

**§3.4 `useSourceImage` 판단 기준 문단 교체**
> 🔴 `useSourceImage`(원문 `sourceUrl`의 썸네일)는 지금도 `false`로 둔다. 카드에 실제 사진을 쓸 때는 `useSourceImage`가 아니라 `image.kind: public`·`news`(§3.6)를 쓴다. 인물 사진은 `planning/card-image-policy.md` §3의 얼굴 기준(2안: 공인의 공적 활동 사진 허용, 수행원·통역·배석자 정면 허용, 비공인·미성년자·피해자·부상 장병·일반 시민 제외)을 따르고 판정 근거를 `faceNote`에 적는다.

**§3.6 신설 — 대표 이미지 `image.kind`** (🆕 15-1: news·public 예시를 나눈다 — news에 `license`를 쓰면 빌드 오류, 리뷰 32 P2-4)

news (언론 기사 핫링크):
```yaml
image:
  kind: news
  src: https://…/og-image.jpg      # 근거 기사 og:image(https 핫링크, 내려받지 않는다)
  alt: "사진에 보이는 사실만 쓴 문장"
  caption: "촬영 시점·장소, 직위 이름이 …하는 모습(원 기사 사진 설명 기준). …"   # 필수(정책 §3.6). 160자 이내 권고
  creditName: 연합뉴스               # 사진 권리자 표기(사진 설명의 크레딧). 없으면 기사 매체명
  creditNameEn: Yonhap News Agency
  sourcePageUrl: https://…         # 이 게시물 sources[]의 언론 기사 url과 글자 그대로 같을 것
  retrievedAt: 2026-11-09          # 확인일
  faceNote: 현직 국회의원 — 본회의 발언 — 원 기사 사진 설명   # 얼굴 없으면 "얼굴 없음(건물)"
  # license 줄은 쓰지 않는다(쓰면 오류)
```
public (공공누리 제1유형, 저장소에 저장):
```yaml
image:
  kind: public
  src: /images/{id}/thumb.jpg
  alt: "사진에 보이는 사실만 쓴 문장"
  caption: "…"
  creditName: 기관명
  creditNameEn: Institution name
  sourcePageUrl: https://…         # 공공누리 마크를 직접 확인한 원문 페이지
  license: kogl-1                  # public만 필수. kogl-1만 받는다
  retrievedAt: 2026-11-09
  faceNote: 얼굴 없음(건물)
```
- `kind`를 생략하면 `self`(운영자 제작·SNS 원문 이미지 저장본)다. `self`에는 크레딧 필드를 쓰지 않는다.
- public·news는 `sourceType: url` 게시물의 `image`에만 쓴다. `images[]`(사진 유형 갤러리)는 self만 받는다.
- 포털(네이버·다음·네이트·줌 계열·단축·집계 주소, 이미지 CDN 포함) 주소는 `src`·`sourcePageUrl` 모두 막힌다. 원 매체 기사를 쓴다.
- 상세 사진 아래에 `사진: {creditName}` + 원 페이지 링크와 **사진 설명**이 나온다(영어 상세는 `creditNameEn`·`imageCaption`). 카드에는 나오지 않는다. 공유 미리보기(OG)·구조화 데이터에는 들어가지 않는다.
- 이미지를 내릴 때는 `image` 블록을 지우고 배포하면 된다(새 대체 카드로 바뀐다). 절차는 `planning/image-removal-procedure.md`.
- 깨진 핫링크 점검: `npm run check:hotlinks`(빌드를 막지 않는다). **주 1회**, 담당 업로더.

**§8 표에 추가**
| `image.kind` 값 오류, news `src`가 https 아님·포털, `sourcePageUrl`이 `sources[]` 언론 기사와 다름·포털, public·news 필수 필드 누락(`caption` 포함, C2 반영 후), public `license`가 kogl-1 아님, news에 `license`, `images[]`나 사진 유형에 public·news | 빌드 중단 |
| self 이미지에 크레딧 필드 | 경고만 |
(§8의 "폐지된 필드 … `kind`"는 **최상위** `kind`(게시물 종류)다. `image.kind`와 다르다는 한 줄을 덧붙인다.)

**§9 영어본**: `imageAlt`·`imageCaption`은 news·public에서도 필수다(원본에 `caption`이 있으면 `imageCaption` 필수 — 기존 규칙). 크레딧은 영어본에 따로 적지 않는다 — 원본의 `creditNameEn`이 쓰인다.

### 2.5 공공누리 작성연도·저작물명 필드 필요 여부 (프로그래머 13 미해결 2, 디자인 notes 구현 범위 16)
**판단: 지금은 필요 없다. 단 A를 처음 쓰는 건이 생기기 전에 필요하다.**
- 공식 출처표시 예시는 `작성연도`·`저작물명`을 넣게 되어 있다. 현재 구현은 "본 저작물은 {기관명}에서 공공누리 제N유형으로 개방한 저작물을 이용하였습니다."로 줄였다.
- 리뷰 30 재분류에서 **A 확정이 0건**이라 지금 쓰는 공공누리 이미지가 없다. 따라서 필드를 지금 추가해도 쓰는 곳이 없다.
- **조건부 항목 C9**: A로 쓸 사진이 처음 나오는 시점에 프로그래머 오더로 `workTitle`(저작물명)·`workYear`(작성연도, 연도 숫자)를 public 전용 필수 필드로 추가하고, 공식 문구를 `본 저작물은 {기관명}에서 {workYear}년 작성하여 공공누리 제{N}유형으로 개방한 '{workTitle}'을 이용하였습니다.`로 바꾼다. 업로더는 A를 쓰려면 먼저 슈퍼바이저에게 알린다(`card-image-uploader-steps.md` 단계 2).

### 2.6 크레딧 필드 분리 여부 (리뷰 30 수정표 #17, 프로그래머 13 미해결 3)
**판단: 분리하지 않는다.** `creditName`을 **사진 권리자 표기**(사진 설명의 크레딧, 없으면 기사 매체명)로 정의한다(정책 §5.2). 기사 매체는 `sources[]`에 이미 있고 상세에 기사 링크가 있다. 코드 변경 없음, 업로더 지침과 README 문안에 정의를 반영했다.

### 4.4 `updatedAt` 규칙 (🆕 리뷰 32 P3-7)
- 이 게시물처럼 **문구를 고치는 건**(이니셜 처리·본문 문장 수정)은 `updatedAt`을 오늘 날짜로 바꾸고 PRD §6⑤ "갱신 이력 한 줄"(실명 → 이니셜로 되돌린 사실 포함)을 남긴다.
- 이미지 교체·포털 주소 교체만 하는 건은 내용 변경이 아니므로 `updatedAt`을 바꾸지 않는다(바꾸면 67개 카드에 "MM/DD 갱신"이 7일 붙는다). 업로더 지침 단계 3·4.

### 4.5 남는 문제 (슈퍼바이저 판단)
1. **ID·슬러그·이미지 폴더 이름에 실명(로마자)이 있다** (🆕 16: 사용자 결정 Q1=b — 새 id `2026-08-06-owloffreedom-707-commander-sentencing`로 옮기고 옛 주소는 308으로 넘긴다. 사양 `planning/q1-redirect-q2-sns-image-plan.md` §1, 코드 C11, 내용 작업 업로더 02. 아래는 결정 전 판단 기록): `/post/{id}`·`/en/post/{id}`·사이트맵·canonical·hreflang에 남는다. 위험 **중**(리뷰 32 §5.3). 안정 ID 원칙(PRD §3.1 "한 번 게시된 후 값 변경 금지") 때문에 바꾸려면 **사용자 결정(Q1)** 이 필요하다. 바꾸면 새 id + 옛 id `retired-ids.txt` 등록 + 리다이렉트 코드(지금 `next.config.ts`에 redirects 없음)가 필요하고, 반응·공유수·댓글(v0.4~v0.6)이 아직 없어 지금이 비용이 가장 낮다. 이 문서는 바꾸라고 권하지 않고 사용자에게 올릴 것을 권한다.
2. **직함 + 이니셜의 식별 가능성**: "전 707특임단장 ㄱ씨"는 직함만으로 특정될 수 있다. §6③ 문언은 충족하지만 실질 비식별은 아니다. 저장소가 **공개**라 지난 커밋에 실명이 남는다는 점도 함께 사용자에게 알린다.
3. **확정 시 복귀**: 항소심·상고심에서 유죄 확정 보도가 나오면 §6③ 예외로 실명 표기가 가능하다(§6⑤ 갱신 규칙). 그때까지 이니셜. 정보사 계획처장은 1심 무죄이므로 확정 무죄가 아니어도 확정 유죄 전까지 이니셜이다.
4. **다른 게시물의 비공인 실명(전수 점검 필요)**: 이 건에서 본문 실명 4인 중 1명이 비공인이었다. 표본으로 갈음하지 말고 `content/` 전수 점검이 필요하다(리뷰 32 §9). 별도 오더 사안이다.
5. **#67 대진연 게시물**(이미지 없음 권고): 사진과 별개로 본문에서 비공인 단체 구성원의 표기를 점검하는 것을 권한다.
6. **기획 문서·트리거의 실명 표기**: 이 5개 문서에서는 실명을 뺐다. 기획자 15 트리거(`docs/triggers/planner-15-prd-v0.9-COMPLETE.md`)에 실명 1곳이 남아 있다 — 슈퍼바이저가 같은 방식으로 고칠지 판단한다(이 오더 수정 범위 밖이라 두었다).
