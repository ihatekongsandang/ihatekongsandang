## 단계 0. 포털 출처를 원 매체로 바꾼다 (게시물 46개 파일, 포털 주소 59건)

**규모(2026-11-09 직접 집계)**: `content/posts/` 46개 파일에 포털 주소 59건 — `v.daum.net` 33(그중 `http://` 2), `m.news.nate.com` 24, `news.nate.com` 2. 모두 `sources[].url`이고 `sourceUrl`에는 없다. 영어본(`content/posts-en/`)에는 0건(출처를 원본에서 가져온다).

```bash
grep -lE 'v\.daum\.net|news\.nate\.com|m\.news\.nate\.com' content/posts/*.md        # 대상 파일 (46개여야 한다)
grep -nE 'v\.daum\.net|news\.nate\.com' content/posts/{id}.md                         # 한 파일의 줄
```
(이 목록은 현재 코드의 포털 거부 목록과 같은 호스트를 본다. 다른 포털 주소가 새로 생기면 슈퍼바이저의 확장 점검 규칙을 따른다.)

**건별 절차**
1. 포털 기사 페이지를 열어 **원 매체명·기사 제목·게재일·기자**를 읽는다(보통 기사 상단·하단 "원문 보기" 링크, 매체 로고).
2. 원 매체 사이트에서 **같은 기사**(제목·게재일·기자 일치)를 찾는다(WebSearch로 매체명+제목, 또는 포털의 "원문 보기" 링크). 찾으면 `sources[].url`을 원 매체 주소로 바꾼다.
3. `name`의 접두를 맞춘다: `네이트(경향신문) — …` → `경향신문 — …`. 기사 제목 문구는 그대로 둔다.
4. 날짜(`date`)를 원 매체 페이지의 게재일로 확인한다(`article:published_time` 메타 — guide §3).
5. **원 매체 기사를 확인하지 못하면 그 출처를 제외한다**(PRD §5.4). 제외로 `sources[]`가 허용 출처(§6① — 언론·수사기관·법원) 1건 미만이 되면 **그 게시물은 자동 비공개하지 않고 슈퍼바이저에게 보고**한다(보류 판단은 슈퍼바이저).
6. 원 매체가 PRD §6①의 허용 언론사(등록 매체 등)인지도 함께 확인한다. 아니면 그 출처는 불허다.
7. `npm run --silent validate:content` R=0 + 해당 id 경고 0.

**순서** (🆕 15-1, 리뷰 32 P3-8): 46개 중 **67건 대상은 18개**, 나머지 28개는 이미지 작업과 무관한 PRD §5.4 정리다. 이미지 작업을 막지 않도록 **67건 대상 18개를 먼저** 처리한다. 대상 목록은 `post-recheck.tsv`와 `docs/tools/reviewer-32/portal-count-output.txt`("[67건 대상]" 표시)로 맞춘다.

   이 선택은 건마다 다를 수 있으므로 **파일별 결정을 트리거에 기록**한다.

## 단계 2. 건별 이미지 판정 (B)

**한 건당 이 순서로, 모든 항목을 직접 확인한다. 추정 금지.**

1. **근거 기사 고르기**: 그 게시물 `sources[]`의 `type: 언론` 기사(원 매체 주소, 포털 아님)**에서만** 고른다. 🆕 18: **사진만을 위해 `sources[]`에 출처를 더하지 않는다.** 출처 밖 기사에서 쓸 만한 사진을 찾으면 그 기사는 **"참고 후보"로 트리거에 기록만** 하고(주소·og:image·사진 설명·판정 근거) 사진은 쓰지 않는다(묶음 3 #25 선례, 슈퍼바이저 판단 2026-11-11, 사용자 이의 시 변경). 출처를 새로 더할지는 그 게시물의 내용(출처로서의 가치)을 보고 슈퍼바이저가 따로 정한다. 사건 보도 기사일수록 좋다.
2. **og:image 얻기**(이미지를 저장소에 저장하지 않는다)
   ```bash
   curl -sL -A "Mozilla/5.0" "기사URL" | grep -oE '(og:image|og:image:alt|article:published_time)" content="[^"]+'
   ```
   - 이미지 주소가 https인지, 로고·기본 이미지가 아닌지 본다.
3. **이미지 열람**: 브라우저로 직접 연다. 크기 확인이 필요하면 저장소 밖 임시 폴더에 받아 `sips -g pixelWidth -g pixelHeight`로 잰다(**짧은 변 400px 미만 제외**). 열람 뒤 삭제한다.
4. **사진 설명(캡션)·크레딧·사용 제한 표기 수집**: 원 기사 HTML에서 대표 이미지 `figcaption`(없으면 이미지 `alt`)과 기사 본문의 사진 설명을 읽는다. 기록할 것: 인물(직위·이름), 촬영 일시·장소, 사진 크레딧(연합뉴스·뉴스1·대통령실 제공 등), **사용 제한 표기**("재배포 금지"·"DB 금지"·"국내에서만 사용"·"재판매 금지"). 첫 `figcaption`이 대표 이미지 설명이 아닌 기사도 있으니 이미지와 맞는지 눈으로 확인한다.
   - **캡션이 없는 인물 사진은 쓰지 않는다.**
   - 사용 제한 표기가 있으면 제외. 일반 고지("무단 전재 및 재배포 금지")만 있으면 제외 사유가 아니다.
5. **정책 §5.3 제외 12항 전부 점검**: 7종 사유 · 비공인 얼굴 · 확정 전 비공인 규칙 · 로고/기본 이미지/SNS 캡처/스톡/글자 중심 그래픽(지도는 "지명·축척·범례·방위·번호 표지 외 문장 없음"일 때만) · 게시 불가 SNS 캡처 · 사진 설명과 기사 맥락 불일치·다른 사건 · 사용 제한 · 품질 · 신원 추정 · 조롱·수갑·수의 장면 · 🆕 **자막 단정형 화면**(의혹·혐의·판결을 단정·요약하는 자막·글자가 이미지에 박힌 것) · 🆕 **12항 명패·이름표·현판·간판의 이름**(원본 해상도에서 읽히는 비공인 실명 또는 의혹 대상으로 지목된 비공인 단체·사업장 이름 — 글자를 직접 읽어 확인).
6. **인물 판정**(정책 §3): 직위를 사진 설명·명패·기사 본문으로 확인 → 공인 범위표(§3.1, 🆕 특별검사·특별검사보 포함 — 직위를 사진 설명·기사로 확인한 경우만) 대조 → 공적 활동(§3.2) → **인물 3분류**(§3.3: (가)주인공 · (나)3b 부수 인물 — (가)가 있을 때만 · (다)그 밖 — **원경일 때만**) → 항상 제외(§3.4). "정장·국회 배경이면 의원" 같은 추정 금지. 🆕 **주인공·공동 주인공 중 사진 설명으로 신원을 확인하지 못한 사람이 있으면, 또는 (다) 인물이 원경 기준(단계 2-1)을 넘으면 쓰지 않는다**(9항). 원경으로 허용되는 (다)와 (가)가 있을 때의 (나)는 9항 대상이 아니다.
7. **같은 사건·사건 당시(4a)**: 사진의 촬영 시점·장소가 게시물 사건과 같은지 확인(정책 §5.1). **인물이 없는 건물·장소·장비 사진도 같다** — 사진 설명 또는 기사 본문이 촬영 시점을 밝히고 사건 시점과 같을 때만 쓴다. 표기가 없거나 "자료사진"·"파일 사진"이면 불가. 확인한 문장을 트리거에 한 줄 적는다. 판정 못 하면 불가.
8-0. 🆕 **덧씌우기 금지**: 이 사이트가 이미지 위에 글자·도형·로고를 얹지 않는다(정책 §5.1).
8. 하나라도 걸리면 다른 근거 기사로 1번부터 재시도한다. 근거 기사가 더 없으면 **B 불가**(이미지 없음, 트리거에 사유).

## 단계 2-1. 원경 측정 (🆕 기획자 17 — 정책 §3.3 원경 기준)

**언제**: 단계 2의 6번에서 사진에 (다) 인물(기자·경호 요원·일반 참석자·방청객·행인·군중·신원 미확인 인물)의 **정면 얼굴이 하나라도 알아볼 수 있게** 보일 때. (다)가 뒷모습·옆모습·흐림뿐이거나 사람이 없으면 재지 않는다(크기 무관 허용). 🔴 **(나)가 될 수 있는지 먼저 본다**: (가)를 사진 설명이 지목했고 그 사람이 (가)의 공식 일정에서 공무 수행 중인 수행원·통역·배석자라고 사진 설명·본문으로 확인되면 (나)로 허용하고 재지 않는다. 확인되지 않으면 (다)로 본다.

**기준 이미지**: 근거 기사 og:image를 **받은 그대로의 원본 해상도**로 본다. 확대해서 재지 않는다(확대하면 5%가 달라 보인다). 저장소 밖 임시 폴더에 받아 두고 끝나면 지운다.

**재는 방법**
1. 짧은 변 y px를 잰다: `sips -g pixelWidth -g pixelHeight <파일>` → 둘 중 작은 값 = y.
2. (다) 정면 얼굴을 **전부 찾는다**(배경·가장자리·뒤쪽 줄까지). 가장 커 보이는 얼굴 1~3개를 골라 잰다.
3. 얼굴 높이 x px = **이마(헤어라인)에서 턱 끝까지**의 세로 길이다. 원본 픽셀 좌표로 잰다: 이미지 뷰어(미리보기 등)에서 원본 크기(100%)로 열어 두 지점의 세로 좌표 차이를 읽거나, 해당 영역을 확대 없이 잘라 `sips`로 높이를 확인한다. 머리카락·모자는 넣지 않는다. 고개를 숙이거나 기울어 이마·턱이 가려지면 보이는 최대 높이로 재고 "약"을 붙인다.
4. 비율 = x ÷ y × 100(%). **가장 큰 얼굴**의 비율이 판정 대상이다.

**판정**
| 가장 큰 (다) 정면 얼굴의 비율 | 결과 |
|---|---|
| **4.5% 미만** | 한 번 재서 원경 후보 — 아래 ②③도 충족하면 허용 |
| **4.5% 이상 5% 미만** | **재측정**: 앞 값을 보지 않고 다른 시점에 처음부터 한 번 더 잰다. **두 번 모두 5% 미만일 때만** 원경 후보(②③ 충족 시 허용). 한 번이라도 5% 이상이면 불가. 두 값을 모두 기록 |
| **5% 이상** | **불가**(재측정 없음) |
- ② **초점·화면 중심의 대상이 아니다**: 사진이 그 사람을 보여 주려고 찍은 것이 아니고, 화면 중앙·앞줄에 두드러지지 않는다. 판단이 갈리면 불가.
- ③ **사진 설명이 그 인물을 언급하지 않는다**: 사진 설명(원문 HTML)에서 이름·직위·역할로 개별 인물을 가리키면 언급이다. 총칭("참석자들")은 개별 지목이 아니다. 애매하면 불가.
- 미성년자·피해자·부상자로 보이면 크기와 관계없이 불가(§3.4). 판정이 애매하면 **불가로 쓴다.** 5% 근처에서 축소해 5% 미만으로 맞추지 않는다.
- 5%는 **확정 수치**다(사용자 채택 2026-11-10). 허용 상한은 **5% 미만 그대로**이고 경계 불가 구간은 없다(사용자 결정 2026-11-10, 정책 §3.3). "잠정"으로 적지 않는다.

**기록 형식**(`faceNote`는 단계 3, 트리거는 단계 4)
- `faceNote`: `…; 원경 인물 n명(얼굴 최대 약 x px / 짧은 변 y px)`. (다)가 뒷모습·옆모습·흐림뿐이면 `원경 인물 n명(뒷모습·옆모습·흐림 — 정면 없음)`. 인원이 많아 세기 어려우면 `원경 인물 n명 이상`을 쓴다(예: 군중 전경, 정책 §3.5).
- 트리거(건별): (다) 인물 수 n, 가장 큰 얼굴 x px, 짧은 변 y px, 비율 %(4.5% 이상 5% 미만이면 두 번의 측정값 모두), 그 얼굴의 위치(예: 오른쪽 아래), ②③ 판단 한 줄. 불가면 잰 값과 사유("5.2% — 5% 이상 불가", "4.7%·5.1% — 재측정에서 한 번 5% 이상 → 불가", "사진 설명이 직위로 언급 → ③ 위반" 등). 이름은 쓰지 않는다.
- 이 규칙으로 허용되는 사진도 그 사진의 §5.3 나머지 항(워터마크·4a·400px·사용 제한 등)은 그대로 점검한다. **원경 허용은 9항·2항만 푼다.**

> A는 조사 결과 확정 0건이다. A를 쓰려는 사진이 새로 나오면 정책 §4를 따라 해당 페이지에서 **공공누리 마크·유형을 눈으로 확인**하고, 제1유형만 `public/images/{id}/thumb.jpg`로 저장한다. 공식 문구의 `작성연도`·`저작물명` 필드가 필요하므로 **A를 처음 쓰는 건이 생기면 먼저 슈퍼바이저에게 알린다**(프로그래머 오더 필요).

## 단계 3. frontmatter 작성 (13 스키마)

기존 `image:` 블록(`src: /images/{id}/thumb.jpg`·`caption: …자체 제작`)을 **교체**한다. `useSourceImage: false`·`og:`는 그대로 둔다.

```yaml
image:
  kind: news
  src: https://img.example.news/og/abc123.jpg        # 근거 기사 og:image(https) 그대로. 내려받지 않는다
  alt: "국회 본회의장 단상에서 발언하는 정장 차림의 인물"   # 사진에 보이는 것만. 인물의 신원·의혹을 적지 않는다
  caption: "2026-10-07 국회 본회의, 현직 국회의원 ○○○ 의원이 발언하는 모습(원 기사 사진 설명 기준). 사진 속 인물이 이 게시물이 다루는 의혹의 당사자임을 뜻하지 않습니다."
  creditName: 연합뉴스                                  # 사진 권리자 표기(사진 설명의 크레딧). 없으면 기사 매체명
  creditNameEn: Yonhap News Agency
  sourcePageUrl: https://news.example.com/article/12345   # sources[]의 언론 기사 url과 글자 그대로 같아야 함
  retrievedAt: 2026-11-09                                # 확인일(미래 날짜 불가)
  faceNote: 현직 국회의원 — 본회의 발언 — 원 기사 사진 설명; 원경 인물 3명(얼굴 최대 약 18 px / 짧은 변 724 px)    # 공인 판정 근거. 3b 수행원이 정면이면 "수행원 정면 포함(3b)" 덧붙임. (다) 원경 인물이 있으면 "원경 인물 n명(얼굴 최대 약 x px / 짧은 변 y px)"(단계 2-1)
```
- `license`는 news에 쓰지 않는다(쓰면 오류 — 리뷰 32가 재현). `license: kogl-1`은 `kind: public`에만 쓴다(정책 §8 public 예시). `images[]`에 같은 이미지를 넣지 않는다.
- 🆕 **`updatedAt` 규칙(리뷰 32 P3-7)**: 이미지 교체·포털 주소 교체만 한 건은 **`updatedAt`을 바꾸지 않는다**(바꾸면 카드에 "MM/DD 갱신"이 7일 붙는다). **본문·제목 문구를 고친 건**(#1 이니셜화, "자체 제작 카드를 썼습니다" 문장 수정이 사실 정정인 경우 포함)은 `updatedAt`을 오늘로 바꾸고 PRD §6⑤ 갱신 이력 한 줄을 남긴다. 판단이 갈리면 슈퍼바이저에게 묻는다.
- `retrievedAt`은 그날 직접 열어 확인한 날짜다.
- 영어본 `content/posts-en/{id}.md`: `imageAlt`·`imageCaption`을 번역한다(`creditNameEn`이 크레딧으로 쓰인다). `content/README.md` §9 문체를 따른다. 🔴 **옛 텍스트 카드의 영어 `imageAlt`·`imageCaption`("Summary image made by this site …")이 새 사진 아래 그대로 남아도 검증이 잡지 못한다**(리뷰 32 재현). 영어본의 두 줄을 **새 사진 기준으로 반드시 교체**하거나, 이미지를 지운 건은 지운다. 이미지 없음 건의 영어 본문에 남은 "자체 제작 카드" 문장도 함께 본다.
- 옛 텍스트 카드: **새 이미지로 바꾸면** `public/images/{id}/thumb.jpg`(옛 카드)를 삭제한다. 이미지 없음(B 불가)인 건도 옛 텍스트 카드를 쓰지 않으므로 `image:` 블록과 옛 파일을 지운다. 삭제한 파일은 트리거에 적는다.
- 🔴 본문 문구 갱신: 대상 67개 중 약 **53개**의 본문이 "원문 이미지 대신 자체 제작 카드를 썼습니다" 같은 문장을 갖고 있다(직접 집계: 본문에 "자체 제작 카드·이미지"·"텍스트 카드" 포함 53건). 이미지를 바꾸거나 없앤 건은 이 문장을 **사실에 맞게 고친다**(예: 해당 문장 삭제, 또는 "대표 이미지는 근거 기사의 사진을 원 매체 주소에서 불러와 보여 줍니다"). 이 문장을 고치는 것은 본문 편집이므로 영어본도 맞춘다.
- 판정 기록: 건별로 인물 판정 근거·사용 제한 표기 확인 결과를 트리거에 남긴다. 🆕 인물 판정에는 (가)(나)(다) 분류와, (다) 정면 얼굴이 있으면 단계 2-1의 측정값(n·x·y·비율·위치)을 포함한다.

## 단계 3-1. 의혹 사안 사진 설명 문구 (2b 완화책 ②)

의혹 사안(제목·요약이 의혹·수사·기소·재판(확정 전)을 다루는 게시물)에 **인물(공인) 얼굴이 나오는 사진은 `caption`을 반드시** 쓴다. 다른 사진도 같은 형식을 권장한다(정책이 caption을 public·news 필수로 하는 안을 C2로 올렸다).

| 사진 속 공인이 | 문구 |
|---|---|
| 게시물 의혹의 당사자가 **아님** | `{촬영 시점·장소}, {직위 이름}이(가) {활동}하는 모습(원 기사 사진 설명 기준). 사진 속 인물이 이 게시물이 다루는 의혹의 당사자임을 뜻하지 않습니다.` |
| 게시물 의혹의 당사자 **본인임**(공인) | `{촬영 시점·장소}, {직위 이름}이(가) {활동}하는 모습(원 기사 사진 설명 기준). 이 사진은 해당 일정의 장면일 뿐 게시물이 전하는 의혹·재판 내용의 근거가 아니며, 그 내용은 아래 출처 보도 기준입니다.` |
| 얼굴 없음(건물·장소·장비) | `{촬영 시점·장소}의 {대상}(원 기사 사진 설명 기준).` |

- **160자 이내**(정책 §3.6 — 표 2행 고정 문구만 85자라 120자 기준은 늘 경고가 난다). 운영자 단정·평가 금지. 사진 설명에서 확인한 사실만 쓴다. 비공인 수행원의 이름은 쓰지 않는다(직위·역할만).
- 사진 설명에 촬영 일시·장소가 없으면 인물 사진은 쓸 수 없다.

## 단계 4. 검증·트리거·묶음 게이트

**건마다(필수)**
```bash
npm run --silent validate:content > /tmp/v.log 2>&1; R=$?; grep -A1 '🟡' /tmp/v.log | grep -E "$ID" -A1; tail -2 /tmp/v.log; echo R=$R
```
`R=0` + 해당 id 경고 0. `| tail -1`만 보고 넘어가지 않는다(guide §5).

**트리거** `docs/triggers/poster-image-{묶음번호}-COMPLETE.md`: 건별로 이미지 종류(B/없음)·선택 기사·크레딧·인물 판정 근거·사진 설명 수집 결과(사용 제한 표기 포함)·제외 점검 12항 결과(자막 단정형·명패 포함) · 🆕 인물 3분류와 원경 측정값(단계 2-1)·사건 당시 확인(건물·장소 사진은 촬영 시점 근거 문장)·삭제한 옛 파일·**영어본 alt·caption 교체 여부**·`updatedAt` 변경 여부·R 값. **불가 건은 사유와 시도한 근거 기사 목록.**

**묶음 게이트 체크 항목**: ① 영어본 `imageAlt`·`imageCaption`이 새 사진 기준인가(옛 "자체 제작" 문구 0건) ② `updatedAt`이 규칙대로인가 ③ news 예시에 `license`가 없는가 ④ 제외 12항.
**묶음**: 10건 안팎(첫 묶음 5건). 한 묶음이 끝나면 리뷰어 게이트 → 통과 후 슈퍼바이저 커밋·푸시. 리뷰어가 육안으로 다시 확인할 수 있도록 건별 이미지 주소·기사 주소·사진 설명을 표로 준다.

**guide의 현행 문장과의 충돌**(슈퍼바이저가 반영 시 정리): 정책 §9 참조.

## 단계 5. 주 1회 핫링크 점검 (2b 완화책 ③)

**담당**: 업로더. **일정**: 슈퍼바이저가 설정한다(요일·반복 방식은 슈퍼바이저가 정해 `docs/operations/hotlink-check-log.md` 머리에 적는다).

1. 최신 `main`에서 실행한다. 배포 조건과 같은 Referer로 묻는다.
   ```bash
   NEXT_PUBLIC_SITE_URL=https://ihatekongsandang.vercel.app npm run check:hotlinks
   ```
   (이 점검은 빌드를 막지 않는다 — 종료 코드는 항상 0. 요약의 `깨짐` 건수와 `BROKEN` 줄을 읽는다.)
2. 깨짐(`BROKEN`)이 있으면 **그 게시물 상세·피드에서 새 대체 카드로 바뀐 상태**다. 바로 처리하되 일시 오류를 가려낸다: 같은 주소를 다시 요청해 보고(다른 시간대에 1회 더), 그래도 안 열리면 진행한다.
3. 처리: ① 같은 기사에서 새 `og:image`를 구해 **단계 2를 처음부터 다시** 판정한다 ② 다른 근거 기사로 교체한다 ③ 없으면 **`image:` 블록을 삭제**한다(이미지 제거와 같은 한 줄 조치, `image-removal-procedure.md` §4.1). 슈퍼바이저가 커밋·배포한다.
4. **기록**: `docs/operations/hotlink-check-log.md`에 한 줄 — `점검일 · 점검 건수 · 정상 · 깨짐 · 조치(교체/삭제/일시 오류)`. 같은 매체가 반복해서 깨지면 슈퍼바이저에게 알린다(정책 §10).
5. **월 1회 육안 점검**(권고, 슈퍼바이저 승인 필요): 위 점검은 "이미지가 열리는지"만 본다. 원 매체가 **같은 주소의 사진을 다른 사진으로 바꾼** 경우는 잡지 못한다. 한 달에 한 번 B 게시물 전부의 상세 페이지를 열어 사진이 `alt`·사진 설명과 맞는지 본다. 맞지 않으면 3번 ③으로 처리한다. (코드로 변경을 감지하는 안은 `v0.9-copy-and-code-list.md` C8.)
