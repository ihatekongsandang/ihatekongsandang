# 이미지 제거 절차 (카드 대표 이미지 — 공공누리·언론 핫링크)

**작성**: 기획자 15 (Sonnet 5.5) | **작성일**: 2026-11-09 | **상태**: 확정(사용자 결정 2b의 완화책 ①)
**근거**: `planning/card-image-policy.md` §5.5·§7 · PRD v0.9 §5.1 4항·§6④ · 약관 `planning/terms-page-copy.md`(처리 기준)
**정정**: 기획자 15-1 (Sonnet 5.5, 2026-11-09) — 리뷰 32 P3-9 반영(§2.2 저장소 공개 확인, self 이미지 요청 경로).
**운영 주체**: 사용자(운영자)가 요청을 받고, **슈퍼바이저가 조치 파일을 만들고, 업로더가 배포 전 검증·기록**한다(실제 커밋·배포는 슈퍼바이저).

> 🔴 저장소 독립 원칙: 이 문서에는 다른 서비스명·계정·홈 경로를 쓰지 않는다.
> 개인정보 주의: 요청자의 이름·연락처·메일 본문은 **저장소(기록 파일)에 쓰지 않는다**. 기록에는 접수일·대상 게시물 id·요청 유형·조치만 남긴다.

---

## 1. 핵심 한 줄
**이미지는 해당 게시물 frontmatter의 `image:` 블록을 지우고 배포하면 내려간다.** 카드·상세는 새 대체 카드로 바뀐다. 게시물은 그대로 남는다. 이 한 번의 조치로 끝나도록 만든 것이 2b 완화책 ①의 목적이다.

## 2. 접수 경로

### 2.1 현재 상태 (연락 창구 확정 전) — 사실
- 사이트에는 **요청을 받을 경로가 없다.** `/about`·`/terms`(ko/en)는 "연락 창구 준비 중" 상자만 보인다(`contactEmail`은 `null`, 사용자 결정 4c).
- 사용자가 이 상태를 알고 공인 얼굴 B를 먼저 시작하기로 했다(2b). 따라서 **이 절차는 "요청이 어떤 경로로든 사용자·슈퍼바이저에게 닿았을 때"의 처리 기준**이다.

### 2.2 확정 전 임시 접수 (요청이 닿는 경로)
| 경로 | 설명 | 처리 |
|---|---|---|
| 사용자에게 직접 닿은 연락 | 언론사·인물 측·제3자가 어떤 수단으로든 사용자에게 알려 온 경우(저장소 소유 계정 알림, 관련 소셜 계정 메시지 등) | 사용자가 슈퍼바이저에게 **대상 게시물 id(또는 URL)와 요청 취지**만 전달 |
| 외부 신호 | 이 사이트의 이미지에 대한 문제 제기를 사용자나 업로더가 우연히 알게 된 경우(언론사 공지, 공개 게시글 등) | 요청이 아니어도 **같은 절차(§3)를 적용**한다 |
| 저장소 공개 이슈 | 리뷰 32가 확인했다: 저장소는 **공개**이고 이슈 기능이 켜져 있다. 다만 사이트 코드(`src/`)에는 저장소 링크가 없어 방문자가 이슈로 찾아올 길은 사실상 없다("있지만 사이트에서 찾아올 수 없는" 경로) | 이슈가 올라오면 사용자 알림으로 닿는다 — **사용자 알림 설정을 켠다**(사용자 작업). 🔴 **이슈는 공개**라 요청자 정보와 문제 제기 내용이 그대로 공개된다. 처리할 때 **이슈 내용을 이 문서의 기록 파일(§5)로 옮기지 않는다**(기록 파일에는 접수일·id·유형·조치만). 이슈 답변은 사용자가 한다 |

- **이 절차의 범위**: `image.kind`가 news·public인 이미지다. 이미 있는 SNS 원문 이미지 저장본(`self`) 등 그 밖의 이미지에 대한 요청은 이 절차가 아니라 **PRD §6④ 일반 정정·삭제 절차**로 처리한다(리뷰 32 §6). 기록 파일에 쓰는 경우 "종류" 칸에 `self`로 적는다.
- 위 경로 어디에도 "접수받았음"을 알리는 자동 회신이 없으므로, 닿은 요청에는 **사용자가 1차 답변**을 한다(§3의 시한).
- **창구가 확정되면**(PRD §0.5 미결 해소): `contactEmail` 교체 → 약관의 "처리 기준은 … 확정된 뒤부터 적용" 문장이 자동으로 사라진다 → 이 문서 §2를 "공식 창구 1곳"으로 고친다 → `/terms`에 "이미지 제거 요청" 항목 문구 작업을 기획자에게 맡긴다(정책 §10).
- **사용자 작업(권고)**: 창구가 없으면 요청을 받을 수 없으니, 2b로 B를 시작하기 전후로 **전용 연락 창구를 최우선으로 마련**한다(`docs/user-tasks.md` §5). 이 프로젝트 전용 계정이어야 한다(계정 분리 원칙).

## 3. 처리 시한 (기존 약관 기준을 따른다)

| 단계 | 시한 | 근거 |
|---|---|---|
| 1차 답변(접수 확인) | **영업일 3일 이내** | PRD §6④, 약관 |
| **이미지 제거 조치** | **요청을 확인한 즉시**. 이미지 제거는 되돌릴 수 있는 저비용 조치이므로 **판단 전 선제 제거**를 기본으로 한다(내부 목표: 요청 확인 후 영업일 1일 안에 배포) | PRD §6④ "실제 조치는 확인 즉시". 영업일 1일은 내부 목표이며 약관 문구는 바꾸지 않는다 |
| 제거 후 재검토 | 영업일 3일 이내에 복원·교체 여부 판단 | 임시 제한은 최대 30일을 운영 기준으로 둔다(약관 09-1 추가) |

- 우선 처리: **초상·명예 관련 요청**과 **의혹 사안(제목·요약이 의혹·수사·재판을 다루는 게시물) 사진**. 언론사의 사용 중단 요청은 그 즉시 제거한다.

## 4. 조치 방법

### 4.1 이미지만 내리는 경우 (기본)
1. 슈퍼바이저가 대상 게시물 `content/posts/{id}.md`에서 **`image:` 블록 전체를 삭제**한다(`image.kind`가 `news`·`public`인 것).
   - `useSourceImage`·`og`·`sources[]`·본문은 건드리지 않는다.
   - 영어본(`content/posts-en/{id}.md`)의 `imageAlt`·`imageCaption`(있으면)도 지운다(남겨 두면 검증이 "한국어 원본에 image가 없어 쓰이지 않습니다" 안내를 낸다. 오류는 아니지만 정리한다).
   - `public`(공공누리, 저장소 저장본)이면 `public/images/{id}/` 아래 해당 파일도 삭제한다.
2. `npm run --silent validate:content`가 R=0인지 확인한다(해당 id 경고 0).
3. 슈퍼바이저가 커밋·푸시한다(배포). **리뷰어 게이트는 콘텐츠 게시 예외 규정(CLAUDE.md §5)을 따른다.**
4. 배포 후 해당 상세·피드가 새 대체 카드로 나오는지 1회 확인한다(`curl` 또는 브라우저 1회).
5. 요청자에게 조치 완료를 알린다(사용자).

### 4.2 이미지를 다른 이미지로 교체하는 경우
- 이미지 제거 뒤 재검토에서 다른 근거 기사의 이미지로 교체하기로 하면, 업로더가 `card-image-uploader-steps.md` 절차로 새로 판정·작성하고 리뷰어 게이트를 거친다.

### 4.3 게시물 자체를 내리라는 요청
- 이 문서 범위 밖이다. PRD §6④·약관의 정정·삭제 절차를 따른다(요약 문장·출처 수정 또는 비공개).

### 4.4 이 방식이 막지 못하는 것
- 이미 사용자 브라우저·검색엔진·웹 아카이브에 캐시된 화면은 제거되지 않는다. 핫링크는 우리 서버에 사진이 없어 **우리 쪽에서 지울 사본이 없다**는 점은 장점이다(`public` 저장본만 삭제 대상).
- 요청자가 **원 매체 이미지 자체의 삭제**를 원하는 경우는 원 매체에 요청하도록 안내한다(핫링크는 원 매체 이미지가 지워지면 대체 카드로 자동 전환된다).

## 5. 기록 방법
- 기록 파일: `docs/operations/image-removal-log.md`(첫 사용 때 슈퍼바이저가 만든다). **한 요청 = 표 한 줄.**
- 기록 항목(개인정보 제외): 접수일 · 접수 경로(§2.2 분류) · 대상 게시물 id · 이미지 종류(news/public) · 요청 유형(초상·명예 / 언론사 사용 중단 / 저작권 / 기타) · 조치(제거·유지·교체) · 조치일 · 재검토 결과 · 처리자.
- 요청자 이름·연락처·메일 본문은 **쓰지 않는다.** 필요하면 사용자가 별도(저장소 밖)로 보관한다.
- `history/{날짜}.md`에는 한 줄(`## [HH:MM] 이미지 제거 — {id} → …`)을 남긴다.
- 같은 사유(예: 한 매체의 사진 사용 중단 요청)가 반복되면 **정책 재검토 후보**로 슈퍼바이저가 사용자에게 알린다(정책 §10).

```markdown
| 접수일 | 경로 | 게시물 id | 종류 | 요청 유형 | 조치 | 조치일 | 재검토 | 처리자 |
|---|---|---|---|---|---|---|---|---|
| (예) 2026-MM-DD | 사용자 직접 | 2026-MM-DD-매체-주제 | news | 언론사 사용 중단 | image 블록 삭제 | 2026-MM-DD | 영업일 3일 내 교체 판단 | 슈퍼바이저 |
```

## 6. 이 절차가 필요한 이미지 표식
- frontmatter에 `image.kind: news` 또는 `public`이 있는 게시물이 대상이다(`grep -l "kind: news\|kind: public" content/posts/*.md`).
- 업로더는 이미지를 넣을 때마다 이 절차로 **한 줄 삭제가 가능한 구조**를 유지한다(`image:` 블록 하나로 끝나는지 확인). `images[]`·본문에 같은 이미지를 중복해 넣지 않는다(코드가 `news`·`public`을 `image`에만 허용).
