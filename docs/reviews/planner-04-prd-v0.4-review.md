## 2. 결함 확정 (기획자 05 수정 필수)

### K1 (중). §6③ 공인 예외 정의가 두 가지로 읽히고, Q1 반영 문구가 넓은 독법을 강화 — 4단계 이니셜 규칙이 무력화될 수 있음
**위치**: `planning/prd.md` §6③ L291·L292
**인용**:
- L291: `**공인 예외**: 선출직·고위 공직자 등 언론이 이미 실명으로 보도한 인물은 5단계 어디서든 언론 표기를 따른다`
- L292: `1심·2심(비확정) 유죄는 공인 예외와 동일한 규칙(언론이 실명 보도하면 언론 표기를 따르고, 아니면 이니셜)을 적용한다`
**근거**:
1. L291은 (가) "선출직·고위 공직자 등 **지위**를 가진 인물로서 언론이 실명 보도한 경우"(지위 기준 + 조건)로도, (나) "언론이 이미 실명으로 보도한 인물 = 공인"(보도 자체가 기준, "선출직·고위 공직자"는 예시)으로도 읽힌다. v0.3 L271도 같은 문장이었고 리뷰어 03은 (가)로 읽어 판정했다(§2 M1 "선출직·고위공직자는 기소 단계에서도 언론 표기") — **리뷰어 03이 모호성을 지적하지 않은 누락을 함께 기록한다.**
2. v0.4 L292가 1·2심 유죄 규칙을 "공인 예외와 동일한 규칙"이라 부르면서 그 내용을 "언론이 실명 보도하면 언론 표기"로 요약했다. 이 요약은 (나) 독법이다. (나)로 읽으면 소재 특성상(간첩 사건 피고인·피의자는 언론이 실명 보도하는 경우가 흔함) `의혹`·`수사중`·`기소`·`종결` 인물 대부분이 "공인"이 되어 L290 이니셜 규칙과 M1 정정이 실무에서 작동하지 않는다. 또한 (나)라면 L292의 1·2심 규칙은 공인 예외에 이미 포함되므로 별도 문장이 무의미하다 — 문서 내부 논리가 완결되지 않는다.
**수정 요구**: L291을 지위 기준으로 재작성 — "공인 = 선출직·고위 공직자·정당 간부·공공기관장 등 공적 지위의 인물(지위 기준). 그 인물을 언론이 실명 보도한 경우에 한해(조건) 5단계 어디서든 언론 표기를 따른다. **공적 지위가 없는 인물은 언론이 실명 보도하더라도 공인 예외에 해당하지 않는다.**" L292를 "1·2심(비확정) 유죄 단계에서는 공인이 아니어도 언론이 실명 보도하면 언론 표기를 따를 수 있다 — 공인 예외와 **별개의** 완화 규칙"으로 재작성(정책 유지, 문구만 분리).

### K2 (하). §6① `기소` 정의 본문이 사례 1(1심 무죄 → 검찰 항소 중)을 담지 못하고 괄호 예시만 담음
**위치**: `planning/prd.md` §6① L270
**인용**: `` 검사의 공소 제기가 보도·발표된 경우 ~ 판결 전(재판 진행 중 포함), **그리고 유죄 판결이 파기·상소 등으로 효력을 잃어 유죄 판결이 현존하지 않는 재판 계속 상태**(예: 무죄 판결 후 검찰 상소 중, 2심 유죄가 대법원에서 파기환송되어 환송심 진행 중) ``
**근거**: 1심 무죄 → 검찰 항소 중인 사건에는 "효력을 잃을" 유죄 판결이 애초에 없다. 정의 본문의 두 절("판결 전" / "유죄 판결이 … 효력을 잃어")은 모두 해당하지 않고, 괄호 예시 "무죄 판결 후 검찰 상소 중"만 해당한다. 리뷰어 03 M2 제안 문구("공소 제기 후 유죄 판결이 현존하지 않는 재판 계속 상태")는 이 사례를 본문으로 덮었는데, v0.4가 "파기·상소 등으로 효력을 잃어"를 앞에 붙이며 좁아졌다. 운영자는 예시로 값을 고를 수 있으므로 "고를 수 없는 사례"는 아니나, 프로그래머 02가 `content/README.md` §4 라벨 표에 옮길 문장은 정의 본문이다.
**수정 요구**: "공소 제기 이후 **유죄 판결이 현존하지 않는** 재판 계속 상태 전부(판결 선고 전, 무죄 판결 후 검찰 상소 중·상소기간 중, 유죄 판결이 상급심에서 파기되어 재판 계속 중)"로 본문을 재작성하고 예시는 유지.

### K3 (중). §3.1 `closureReason` enum이 배타적이지 않음 — `무혐의`·`기소유예`는 `불기소`의 하위 주문 (리뷰어 03 제안 리스트 자체의 오류)
**위치**: `planning/prd.md` §3.1 L140 · §6① L272 · (원인) 리뷰어 03 보고서 §2 M3 수정 요구
**인용**: L140 `` `종결`은 사유 하위 필드(가칭 `closureReason`) 필수(M3 — 무혐의/불기소/기소유예/무죄/공소기각/공소취소/기타 + 부연 텍스트) ``
**근거 (법령 원문)**: 검찰사건사무규칙 제115조③(리뷰어 조회, 시행 2026-07-01) — 불기소결정의 주문은 `1. 기소유예 / 2. 혐의없음(범죄인정안됨·증거불충분) / 3. 죄가안됨 / 4. 공소권없음 / 5. 각하`. 즉 "무혐의(혐의없음)"와 "기소유예"는 "불기소"의 하위 값이다. 같은 처분을 운영자가 `불기소`로도 `기소유예`로도 적을 수 있으면, M3가 막으려던 "무혐의와 기소유예가 같은 배지로 보임"(리뷰어 03 §2 M3 근거 3)이 enum 안에서 재발한다. 또 `공소권없음`(피의자 사망 등, 리뷰어 03 §3 사례 7)·`죄가안됨`·`각하`·`면소`(법원 종결 유형)는 어느 값에도 정확히 대응하지 않아 `기타`로 몰린다. 이 리스트는 리뷰어 03 §2 M3 수정 요구를 글자 그대로 옮긴 것이므로 **원인은 리뷰어 03의 제안이며 기획자 04의 반영 오류가 아니다.**
**수정 요구**: 상위 분류 `불기소`를 제거하고 처분 주문 단위로 재정의 — 기본값 제안: `혐의없음`(무혐의) / `기소유예` / `죄가안됨` / `공소권없음` / `각하` / `무죄` / `면소` / `공소기각` / `공소취소` / `기타`(부연 필수). 값 명칭은 검찰사건사무규칙 §115③·형사소송법 판결 유형 용어를 따른다. 카드 배지에는 값 그대로, 상세에 부연을 표시. 프로그래머 02 R6 착수 전에 확정.

### K4 (하). §6③ 얼굴 규칙이 `유죄판결` 단계에 대해 비어 있음 (5단계 × 실명·얼굴 매핑에서 1칸 공백)

1. PRD 머리말 L15·§3 L129의 "§7 우선"은 **리뷰어 02 보고서 §7 15항목과 어긋날 때**에 한정된 규칙이다. M3(`종결` 사유)는 §7 15항목에 없다(리뷰어 03 §8 항목 1이 "M2·M3 흡수 여지 — 확장 가능 구조인지"로만 코드에 넘김). 따라서 "§7 우선"이 적용될 충돌 자체가 없고, 리뷰어 03이 **결함으로 확정**한 요구사항이 남는다 — 결함 확정 사항은 PRD를 따르는 것이 게이트 원칙(CLAUDE.md §5)과 일치한다.
2. 리뷰어 04(코드) 보고서 R6가 독립적으로 같은 결론이다: "`schema.ts` 종결 사유·기소 병기 필드 + README §3.4·§4·§5 갱신을 프로그래머 02가 PRD v0.4 커밋 후 반영. 지금은 결함 아님". 두 리뷰어와 슈퍼바이저 판단이 일치한다.
3. 재작업 비용이 실측으로 작다: 리뷰어 04 게이트 케이스 15에서 `종결` + 미지 필드 `closureReason`이 **경고만** 내고 통과함이 확인됐고, `content/posts/` 3건의 `status`는 `기소`·`의혹`·`유죄판결`로 `종결` 게시물이 0건이라 필수화해도 기존 파일이 깨지지 않는다.
**단서**: 순서를 명시해야 한다 — 프로그래머 02의 D1·D2(리뷰어 04 필수)는 K3와 무관하므로 즉시, R6(`closureReason` enum 구현)은 **PRD v0.5에서 K3 확정 후**. 또한 PRD 머리말에 "§7에 없는 신규 요구사항은 PRD가 우선한다(슈퍼바이저 결정 2026-09-21)"를 적어 핸드오프 L60의 "우선순위가 자동으로 정해지지 않는다"를 문서로 닫는다(H2).
