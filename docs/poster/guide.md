# 게시 담당 세션 상시 가이드 (poster)

**작성**: 2026-09-30 | **작성 세션**: 슈퍼바이저 (Opus 5.5) | **담당**: 게시 담당 (Sonnet 5)

사용자가 이 세션에 인스타그램·스레드·유튜브 URL(또는 사진)을 붙여 넣으면, 보도와 대조해 **게시 초안을 작성**한다.
**커밋·푸시는 하지 않는다** — 슈퍼바이저(Opus 5.5)가 초안을 전수 검토한 뒤 커밋·배포한다.

2. `content/README.md` 전체 — 게시 파일 스키마(§2·§3), 제목·요약 규칙(§5), 영어본(§9)

## 1. 판단 3종
| 판단 | 기준 | 산출 |
|---|---|---|
| **게시** | 원문 핵심 주장을 언론 보도·공식 발표·판결로 대조할 수 있음 | `content/posts/{id}.md` + 이미지 + 영어본 |
| **병합** | 같은 사안 기존 게시물이 있고 새 정보가 적음 | 기존 게시물 서두에 "같은 내용을 다룬 [계정 게시물](URL)은 별도 게시하지 않고 여기에 적습니다" 식 한 문장 + 차이점 |
| **보류 / 게시 불가** | 근거 보도 없음 · 구호·참여 독려뿐 · 선거 부정 주장 · 사적 개인 겨냥 · 진위 확인 불가 캡처 | `docs/supervisor/drafts/2026-09-28-held-recheck.md` 끝에 `### 보류 — {플랫폼} @{계정} {코드} (YYYY-MM-DD 검토)` 블록 추가 |
| **주제 전환 게시** (2026-11-05 추가) | SNS 글 자체는 보류·게시 불가지만, 그 안에 **등록 언론·수사기관·법원 자료로 확인되는 별개의 사실**(SNS 글의 결론과 독립된 사실, 또는 그 주장에 대한 공식 대응 보도)이 있고, 그 사실이 §1-1 0항 적격성을 충족하며, 기존 게시물에 없는 사안 | 그 **보도를 원문으로** 새 게시물 작성(§1-1) + held-recheck에 보류·게시 불가 블록과 "주제 전환 → `{id}`" 한 줄 |

### 1-1. 주제 전환 게시 규칙 (2026-11-05, 사용자 지시 · 리뷰 18·19 반영)
SNS 글이 게시 불가여도 그 안에 실제로 보도된 사건이 들어 있으면 버리지 않고 보도를 출처로 새 글을 쓴다. 편집 정책(§2·PRD §6)은 그대로 적용하고 완화하지 않는다.
0. **적격성**: 옮겨 쓸 사실은 그 자체로 §1 '게시' 기준을 충족해야 한다. 그 SNS 글이 없었어도 게시했을 사안이어야 한다. 다음은 주제 전환하지 않는다.
   - 사적 개인의 사망·사고(원인 조사 중이거나 극단적 선택 가능성이 있는 경우 포함)
   - 사적 개인·가족의 사생활
   - 선거 부정 주장 자체를 다룬 보도(공식 수사 절차는 기존 선관위 관련 게시물 갱신으로만)
   - held-recheck에 **사실 자체의 공식 확인**(사망 원인 발표, 수사 결과 등)을 재검토 조건으로 적어 둔 사안. '캡처·원 링크·보도가 오면 재검토'는 제외 사유가 아니다.
1. **원문 = 보도**: `sourceType: url`, `sourceUrl`은 그 사실을 보도한 **원 매체 기사 주소**, `attribution`은 매체명. `sources[]`에 `언론`·`수사기관`·`법원` 중 1건 이상 필수(`기타` 단독 불가). 포털 주소는 `sourceUrl`과 `sources[].url` 모두 금지(PRD §5.4).
   - **id = `{기사 게재일 YYYY-MM-DD}-{매체 약칭}-{주제 kebab}`**. 발단 SNS 계정·코드를 넣지 않는다(§4의 계정 약칭 규칙 대신 이것을 쓴다). 이미지 경로도 같은 id를 쓴다.
2. 🔴 **게시 불가 SNS 글은 링크·계정·캡처·인용 모두 하지 않는다.** 게시물 본문·이미지·영어본·id 어디에도 남기지 않는다. 연결 기록은 held-recheck와 트리거에만 남긴다. 이미지는 보도 기사 기준 §4-1(A·B)만 쓰고, 게시 불가 SNS 글의 이미지·캡처는 계속 쓰지 않는다.
3. **SNS 글의 주장·암시를 옮기지 않는다.** 제목·요약은 보도 내용만으로 새로 쓴다. SNS 글의 문장·카드 문구·사실 나열 순서도 따르지 않는다. SNS 글이 붙인 해석("간첩이다", "부정선거" 등)은 근거 보도가 없으면 넣지 않고, "요약에 넣지 않은 내용"에도 적지 않는다(재확산 방지). 이 칸은 기사 내용 중 뺀 것에만 쓴다.
   - 보도가 그 주장을 **주장으로** 다룬 경우(고소·해명·수사·반박)에는 **헤드라인에 주장 문구가 없는 공식 대응 보도가 있을 때만** 쓰고, 보도 표현 범위 안에서 인용형으로만 적는다. 사생활 의혹에 대한 고소·해명 보도는 대상이 아니다(0항). 제목은 보도된 사실(예: "허위사실 유포 고소")로 시작하고, 주장 문구를 제목 앞부분에 두지 않는다.
   - SNS 주장을 반박하는 것이 목적이면 주제 전환이 아니라 §1 '게시' 판단(§2 팩트체크 틀)으로 검토한다.
4. 실명·얼굴은 PRD §6③ 그대로. 기사 문장은 짧은 인용만 하고 요약은 직접 쓴다(기사 전재 금지).
5. **보도 선택**
   - (a) 시의성: 원문 보도는 **게시 작업일 기준 30일 이내** 보도여야 한다(SNS 글 게시일 이후 보도 포함). 그보다 오래된 보도는 30일 이내의 새 진전 보도가 있을 때만 쓴다(그 경우 원문은 새 진전 보도).
   - (b) 태그는 보도 내용 기준으로 기존 태그에서만 고른다. SNS 해시태그는 옮기지 않는다.
   - (c) 헤드라인에 SNS 주장 문구가 들어간 기사는 `sourceUrl`로 쓰지 않는다(OG 제목이 그대로 노출되므로). 같은 사실을 다른 문구로 보도한 기사를 고르고, 없으면 그 기사는 `sources[]`에만 둔다. 이때 `sources[].name`에는 매체명과 중립 요지를 쓰고, 주장 문구가 든 기사 제목을 그대로 옮기지 않는다(`content/README.md` §3.2 "매체명 — 기사 제목" 형식의 예외).
   - (d) 원문 매체는 복수 보도 중 등록이 확인된 매체를 쓴다. 한 매체 단독 보도만 있으면 요약에 "단독 보도"임을 밝힌다.
6. **기존 게시물이 있을 때**: 같은 사안의 기존 게시물이 있으면 새 게시물을 만들지 않는다. SNS 글에 없던 **새 보도**가 있으면 그 보도만 기존 게시물에 갱신 절로 추가한다. 이때 §1 병합 양식의 SNS 링크 문장("같은 내용을 다룬 [계정 게시물](URL)…")은 쓰지 않는다. 새 보도가 없으면 held-recheck 기록만 남긴다.
7. 이후 발단 SNS 글이 게시 가능해져도 새 게시물을 만들지 않고 주제 전환 게시물을 갱신한다(PRD §6⑤).
8. **트리거**: `판단: 주제 전환 게시`, 발단 SNS URL(기록용), 대조 보도 목록(매체·게재일)과 아래 자기 점검 결과를 적는다.
   - [ ] 0항 적격성 해당 없음 확인 · [ ] `sources[]`에 언론·수사기관·법원 ≥1 · [ ] `sourceUrl`·`sources[].url`에 포털 주소 없음 · [ ] 본문·영어본·이미지·id·태그에 발단 계정·코드·해시태그 없음 · [ ] 원문 보도 게시 작업일 기준 30일 이내(또는 새 진전 보도) · [ ] `sourceUrl` 헤드라인에 SNS 주장 문구 없음 · [ ] `sources[].name`에 주장 문구 없음 · [ ] 원문 매체 등록 확인(복수 보도 중 등록 매체, 단독이면 요약에 명시)

## 2. 편집 정책 (위반 = 반려)
- **출처 기반·단정 금지**: 사실 문장은 모두 "~로 보도됨"·"~라고 밝힌 것으로 보도됨". 운영자 단정 금지.
- 원문이 보도와 다르면 **팩트체크 틀**: 제목 뒤에 "— 다만 …" / "보도로는 …"로 차이를 밝히고, 본문 "요약에 넣지 않은 내용"에 무엇이 왜 빠졌는지 적는다.
- **암시·의혹 제기**(누가 지시했다·통제했다 등)는 근거 보도가 없으면 요약에서 뺀다.
- **사적 개인·미성년자 보호**: 실명 추적·기재 금지(비공인은 직함+이니셜, 대령 이하 군인도 비공인), 얼굴이 나온 이미지는 쓰지 않고 §4-1 기준으로 다른 사진을 찾거나 `image`를 비운다.
- **욕설·혐오 표현·후원 계좌·이메일·연락처는 옮기지 않는다.**
- 5·18 왜곡 주장은 판결·공식 조사로 팩트체크하는 틀로만 다룬다.
- 선거 부정 주장은 선관위·법원 판단이나 언론 보도 근거가 없으면 게시 불가.
- **비밀번호·인증번호 입력 금지.** 로그인이 필요한 콘텐츠는 보류하고 사용자에게 스크린샷을 요청한다.

## 3. 원문 수집 명령
```bash
# 공통 OG 초안
npm run --silent og:draft -- "URL" > /tmp/og.txt

# 인스타그램 — 전체 이미지·캡션 (코드 = /p/{code}/ 또는 /reel/{code}/)
#   🔴 UA는 반드시 "Mozilla/5.0" 그대로. 브라우저 전체 UA(Chrome/… 등)로 바꾸면 JS 전용 페이지(약 50만 바이트)가 와서
#   캡션·이미지가 비어 보인다(2026-10-29~11-08 수집 실패 25건 원인, docs/tools/programmer-10/instagram-collect-report.md).
curl -sL -A "Mozilla/5.0" "https://www.instagram.com/p/{code}/embed/captioned/" > /tmp/ig.html
#   이미지: <img class="EmbeddedMediaImage" … src="…">, 캡션: class="Caption"
#   성공 확인: grep -c 'class="CaptionUsername"' /tmp/ig.html → 1. 0이면 다음 순서로:
#   "may be broken" 문구 있음(embed 차단·삭제) → og:draft 로 og:description·og:image 확인 → 그것도 비면 캡처 요청
#   "may be broken" 문구도 없음(응답 약 50만 바이트 JS 페이지) → UA가 "Mozilla/5.0" 그대로인지 확인하고 위 명령으로 1회 재요청 → 그래도 0이면 og:draft → 캡처 요청

# 스레드 — 공유 링크 해석 후 embed
U=$(curl -sL -o /dev/null -w '%{url_effective}' "공유링크"); P=${U%%\?*}
curl -sL "$P/embed" > /tmp/th.html
#   본문: BodyTextContainer, 미디어: .jpg/.mp4 (s100x100 은 프로필 사진이라 제외)
#   게시 시각: "h:mm PM · Mon d, yyyy" (UTC 기준일 수 있음 — 한국 시각 환산 확인)

# 영상 프레임 추출 (ffmpeg 없음)
qlmanage -t -s 800 -o . file.mp4
```

- 원본 이미지는 다운로드한 뒤 **Read로 직접 보고** alt·caption을 쓴다.

## 4. 게시 파일 규칙 (자주 틀리는 것)
- id = `{원문 게시일 YYYY-MM-DD}-{계정 약칭}-{주제 kebab}` (주제 전환 게시는 §1-1 1항). 파일 `content/posts/{id}.md`, 이미지 `public/images/{id}/thumb.jpg`(public만 — news는 핫링크, 새 SNS 게시물은 원 이미지 저장 금지).
- 최근 게시물의 frontmatter 형식을 그대로 따른다(`sourceType: url`, `useSourceImage: false`, `image{…}`는 §4-1, `og.siteName`, `sources[{type 언론|기타, name, url, date}]`, `tags`).
- **태그**: 한글·영소문자·숫자·하이픈만. `5·18` ✗ → `5-18민주화운동`, `518`·`625`처럼 숫자만 ✗ → `6-25전쟁`. 기존 태그 재사용 우선(`grep -h '^  - ' content/posts/*.md | sort | uniq -c | sort -rn`).
- 출처 name에 `:`가 있으면 따옴표로 감싼다.
- 내부 링크 `/post/{id}`는 `ls content/posts | grep 키워드`로 **실제 id를 확인**한 뒤 쓴다(날짜 틀림 사례 다수).
- 🔴 **새 SNS 게시물은 원 게시물 이미지를 저장하지 않는다**(2026-11-09 슈퍼바이저 판단, 사용자 Q2=b — 기존 저장본 139건은 정리 중). 이미지는 §4-1 순서(A → B → 비움)만 쓴다.
- 🔴 **id·파일명·태그·이미지 폴더에 비공인 실명(로마자 포함)을 쓰지 않는다.** 이미 쓴 경우 id 이전 절차(`planning/q1-redirect-q2-sns-image-plan.md`)를 따른다.
- 🔴 **자체 텍스트 카드는 새로 만들지 않는다**(2026-11-09 사용자 결정 — "별로"). 이미지 순서는 §4-1을 따르고, 쓸 사진이 없으면 `image` 블록을 비워 사이트의 새 대체 카드가 나오게 한다.

## 4-1. 카드 이미지 (2026-11-09 확정 — 기준 `planning/card-image-policy.md`, 절차 `planning/card-image-uploader-steps.md`)
- **순서**: A 공공누리 **제1유형**만(korea.kr 사진은 "텍스트에 한하여"라 불가, 제2·3·4유형 불가) → B 그 게시물 `sources[]`의 **언론 기사 `og:image` 핫링크**(재호스팅 금지·포털 주소 금지·차단 우회 금지) → 없으면 `image` 비움(대체 카드).
- **얼굴**: 공인(정책 §3.1 공인 범위표 — 선출직(국회의원·지방의원·단체장 등)·고위공직자·장성급 이상, 외국 정상·북한 지도자·대통령 배우자·대사)의 **공적 활동** 사진 허용. 공식 행사 수행원·통역·배석자 정면 얼굴 허용. **비공인(대령 이하 포함)·미성년자·피해자·부상자·일반 시민 얼굴은 불가.** 판정 근거는 `faceNote`에 적는다.
- **불가 사진**(정책 §5.3 11항): 다른 사건 자료사진(4a — 그 사건 당시 사진만), 스톡·SNS 캡처·로고·글자 그래픽, 재배포 금지 표기, 자막으로 단정하는 화면, 수갑·호송·조롱 장면, 짧은 변 400px 미만 등.
- 🔴 **public·news 이미지는 모두 `image.caption` 필수**(없으면 빌드 중단), 영어본 `imageCaption`도 필수. 의혹·수사·재판 사안 사진은 정책 §3.6 형식의 설명 문구를 반드시 넣는다. 영어본에 옛 alt·caption이 남아도 검증이 못 잡으니 직접 바꾼다.
- 🔴 **착수 조건**: 얼굴 없는 사진은 지금 가능. **공인 얼굴 사진은 프로그래머 16(소개 문구 C4) 배포 뒤부터** 올린다(그 전에 올리면 소개 페이지 문구가 거짓이 된다).
- 캡션·촬영 시점 정보가 없는 인물 사진은 쓰지 않는다.
- **판단 선례**(리뷰 38·39, SNS 묶음 1·2):
  - 매체 워터마크가 있는 사진은 쓰지 않는다. "재판매·DB 금지" 표기도 불가.
  - 의혹·재판 당사자인 공인 본인의 얼굴은 허용하되 정책 §3.6의 맞는 행(당사자 본인이면 2행)을 글자 그대로 넣는다.
  - 현장 실물(현수막·명패·손에 든 문서)의 글자는 §5.3-11(덧씌운 자막) 대상이 아니다. 단 문구가 단정형이면 제목과 합쳐 읽힐 위험을 따로 본다.
  - 정당 직위가 정책 §3.1 공인 범위표 밖이면(예: 당 법률자문위원장 등 위원회 위원장) 비공인으로 본다. 계급·직위를 계급장·자리 배치로 추정하지 않는다(사진 설명·본문에 적힌 것만).
  - 다른 일정 사진은 제목과 관계없이 쓰지 않는다(4a). 특히 제목이 의혹·비난형이면 공인 얼굴이라도 결합 위험이 크다.
  - 불가 사유는 사진 설명 글자만 보고 적지 않는다. **후보 og:image는 모두 직접 열어 보고**, 크기는 받은 파일에서 잰다(리뷰 40).
  - 계급·직위는 사진 설명뿐 아니라 **기사 본문 전체**에서 찾는다(본문에 적힌 계급도 인정). 깃발·현판·명패 글자는 실제로 읽어 그대로 적는다(리뷰 41). 법령상 장성급 직위를 직위만으로 공인 인정할지는 정책 보완 전까지 쓰지 않는다.
  - 매체가 자기 이미지를 클라우드 저장소(예: `edge.naverncp.com`)에 두는 것은 포털 CDN이 아니다 — 금지는 포털이 전재 기사에 다시 올린 이미지(pstatic·daumcdn·nateimg 등). 판단 근거(같은 호스트가 그 매체 사이트 자체 파일도 내보내는지)를 트리거에 적는다(리뷰 43).
  - 여러 정당이 함께 연 집회는 사진 설명·현장 글자가 정당 공동 행사로 적으면 정당 공식 집회로 본다(리뷰 43). 방송 진행자·앵커는 비공인이다.
  - 판사·검사(퇴직자 포함)는 정책 §3.1 앵커(공수처법 제2조 1호)상 공인이다. 다만 재직·퇴직 사실이 사진 설명·본문에 없으면 신원 미확인으로 둔다. 인사청문 후보자 처리는 정책 보완 전까지 보수적으로(얼굴 사진 쓰지 않음)(리뷰 45).
- frontmatter는 `image.kind`(public/news)·`creditName`·`creditNameEn`·`sourcePageUrl`(= `sources[].url` 그대로)·`license`(public만 `kogl-1`)·`retrievedAt`·`faceNote`·`caption`. 예시는 `content/README.md` §3.6.
- **작업 단위**: 첫 묶음 5건, 이후 10건 안팎. 묶음마다 트리거를 만들고 리뷰어 게이트 후 커밋.
- **주 1회** `npm run check:hotlinks` → 깨진 것 처리 → `docs/operations/hotlink-check-log.md` 기록. HEAD 요청에 404를 주고 GET에는 200을 주는 이미지 서버가 있다 — HEAD 결과만으로 깨짐 판정하지 않는다.
- 이미지 제거 요청은 `planning/image-removal-procedure.md`.
- **영어본 동시 작성**: `content/posts-en/{id}.md` — `content/README.md` §9 + 기존 영어본 문체. description ≤160자(직접 세기), "reportedly" 등 유보 표현 유지, 인명 `Romanized (한글)`.

## 5. 검증 (필수, 건마다)
```bash
npm run --silent validate:content > /tmp/v.log 2>&1; R=$?; grep -A1 '🟡' /tmp/v.log | grep -E "$ID" -A1; tail -2 /tmp/v.log; echo R=$R
```
- `| tail -1`만 보고 넘어가지 않는다(실패 은폐 사례). **R=0 + 해당 id 경고 0**이어야 완료.

## 6. 완료 처리 (건마다)
1. 🔴 트리거 `docs/triggers/poster-{id}-COMPLETE.md` **생성 필수** — 내용: 판단(게시/병합/보류), 원문 URL, 변경 파일 목록, 대조한 보도 목록, 원문과 보도가 다른 점, 검증 R 값.
   보류·게시 불가도 `docs/triggers/poster-hold-{계정}-{코드}-COMPLETE.md`로 남긴다.
