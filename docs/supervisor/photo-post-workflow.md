# 슈퍼바이저 플레이북 — 사진만 받았을 때 게시물 작성 워크플로우

**제정**: 2026-09-21 (사용자 지시) | **담당**: 슈퍼바이저 (Opus 5) | **적용**: 사용자가 URL·설명 없이 **사진만** 건넨 경우

> 사용자 원문: "내가 사진만 올릴 경우가 있을 건데, 그럼 사진 속 텍스트와 사진을 분석해서 관련 기사나 짤, 뉴스 등을 검색해서 피드를 작성해줘야 해."

## 원칙
- 사진만으로 게시하지 않는다. **사진 → 분석 → 검색 → 허용 출처 확인 → 초안 → 사용자 확인 → 게시**. 편집 정책(PRD §6)은 이 경로에도 그대로 적용된다.
- 허용 출처(§6② — 등록 언론사·수사기관·법원) 1건 이상을 찾지 못하면 **게시하지 않고** 사용자에게 "출처 미확인"으로 보고한다(`의혹` 라벨이라도 불가).
- 사진 속 인물·문구는 **추측하지 않는다.** 읽히는 텍스트·식별 가능한 요소만 사실로 쓰고, 검색으로 확인된 것만 서술한다.

## 절차
1. **사진 분석** — 슈퍼바이저가 이미지를 직접 읽는다: ① 보이는 텍스트 전부(OCR, 원문 그대로) ② 장면·물체·로고·날짜·매체 워터마크 ③ 인물 존재 여부(얼굴 식별 가능 여부 — §6③ 판단 근거). 결과를 초안 작업 메모에 남긴다.
2. **검색** — 추출 텍스트·고유명사·사건 키워드로 웹 검색(뉴스·보도자료·판결·짤/밈의 출처). 밈·짤은 **원 출처(어느 보도·발언·사건에서 파생됐는지)** 를 찾는다.
3. **출처 선별** — §6② 허용 출처만 `sources[]`에 넣는다(등록 언론사 여부는 정기간행물 등록관리시스템으로 확인). 커뮤니티·SNS·유튜브는 출처가 아니라 검색 단서일 뿐.
4. **상태 라벨** — 확인된 출처 기준으로 `의혹/수사중/기소/유죄판결(심급)/종결` 중 하나. 출처가 라벨을 뒷받침하지 못하면 낮은 단계로.
5. **초안 작성** — 유형은 `photo`(캡션) 또는 `photo_text`(본문). 제목·요약은 §6④ 인용문 형태("~로 보도됨"). 실명·얼굴은 §6③(기소 전 이니셜·얼굴 비노출, 공인 예외). 사진 자체에 얼굴이 식별되면 사용자에게 알리고 게시 여부·처리 방법을 묻는다. `alt` 필수.
6. **사용자 확인** — 초안(제목·요약·라벨·출처 목록·사진 처리 방식)을 사용자에게 보여주고 승인 후 `content/posts/`에 작성 → `npm run validate:content` 통과 → 커밋·푸시.
7. **기록** — history에 "사진 게시: 추출 텍스트 요약 · 검색어 · 채택 출처 N건 · 제외 출처 N건(사유)"를 남긴다.

## 도구
- 이미지 읽기: 슈퍼바이저 세션의 이미지 Read(비전). 별도 OCR 라이브러리 불필요.
- 검색: 슈퍼바이저 세션의 WebSearch/WebFetch. 배포 도메인 접근과 무관.
- 검증: `scripts/validate-content.ts`(프로그래머 01), 등록 언론사 조회 `https://pds.mcst.go.kr/pds/`.

## 미결
- 저작권: 사용자가 건넨 사진의 권리는 사용자 책임 전제(사용자 확정 — 확인 절차 없음). 단 사진이 **언론사 보도 화면 캡처**인 경우 원문 전재에 해당할 수 있어 `url` 유형(원문 링크 카드)으로 전환할지 사용자에게 제안한다. → 기획자가 PRD §5.2에 규칙화(다음 오더).
