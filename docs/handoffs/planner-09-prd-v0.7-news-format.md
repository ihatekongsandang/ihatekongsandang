## 주요 결정사항 (자체 판단 + 근거)
1. **이용약관 페이지 경로를 "제안"으로만 적었다**(`/terms`·`/en/terms`). 오더가 "정해지지 않은 것은 사용자 결정 필요로 표시"라고 했는데, 경로는 사용자가 결정할 사안이 아니라 프로그래머가 구현 시 정하는 기술적 사안이라고 판단해 "제안, 확정은 프로그래머"로 구분했다. 연락 경로(이메일)만 진짜 "사용자 결정 필요" 항목으로 남겼다.
2. **§6⑥(나)에 "적용 범위" 단서를 명시적으로 넣었다** — 금지 표현이 "운영자가 직접 쓰는 편집 문구"에만 적용되고 보도 인용·원문 헤드라인에는 적용되지 않는다는 점을 PRD 본문에 직접 써 뒀다. 그렇게 하지 않으면 다음 세션이 전수 조사 결과(기자 61건)를 보고 content를 잘못 뜯어고칠 위험이 있다고 판단했다.
3. **공유수 집계 "시작점"을 PRD §7 v0.5에 명시했다** — 뉴스형 기획서(08-1) D4 결론을 PRD 본문에도 반영하지 않으면 다음 세션이 과거 클릭을 소급 집계하려 시도할 수 있다고 봤다.
4. **§9 JSON-LD 설명에서 "신중 검토"라는 종전 모호한 표현을 "Article 유지로 확정"으로 바꿨다** — D3가 사용자 결정으로 "전부 권장"에 포함됐으므로 PRD 차원에서는 확정 서술이 맞다고 판단했다(기획서 쪹 `news-format-conversion.md`의 D3는 여전히 "변경 요청 없으면 유지"라는 질문형이지만, 이번에 사용자가 실제로 "권장안 그대로"를 택했으므로 PRD에는 결과를 확정으로 적어도 된다).
5. **금지 표현 조사에서 "앞당기자"(기자 포함 오탐) 등 false positive를 걸러내고 실제 맥락을 읽어 분류했다** — 단순 grep 건수만 보고하면 오해를 부를 수 있다고 판단해, 성격(보도 인용 vs 운영자 자칭)을 직접 읽고 분류했다.

## 미해결·이슈 (다음 세션이 알아야 할 것)
- 연락 경로가 정해지면 `planning/terms-page-copy.md`의 두 "🔴 연락 경로" 자리와 `/about` 페이지 기존 placeholder를 함께 교체해야 한다(프로그래머·슈퍼바이저).
- `/en/about`에는 현재 "소개 문단"이 없다(번역 안내·정정요청만 있음) — D1 소개 문구를 영어판에 처음 추가하는 작업이 된다(scope 문서 2.1에 적어 뒀다).
- 전역 푸터 컴포넌트의 실제 존재·위치를 이번 세션에서 확인하지 않았다(코드·content 수정 금지라 탐색만 하고 깊이 들어가지 않음) — 프로그래머가 착수 시 확인.
- PRD §9 JSON-LD 설명과 `news-format-conversion.md` D3 문구("변경 요청 없으면 유지" — 질문형)가 톤이 다르다(위 결정사항 4). 다음 기획자 오더에서 `news-format-conversion.md` D3도 "결정됨"으로 갱신할 필요가 있다(이번 오더 범위 밖이라 손대지 않음).
