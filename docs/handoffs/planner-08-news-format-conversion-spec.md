## 요약 (3줄)
- 뉴스형 전환(등록 없음)을 §1 정체성·법적 선 ~ §6 로드맵 6개 절로 기획했다. 신문법·언론중재법·정보통신망법·네이버 뉴스제휴 기준·Google 뉴스 Publisher Center·schema.org NewsArticle 서브타입을 공식 1차 출처로 확인했다.
- 핵심 결론: 등록 미등록은 명칭이 아니라 기능적 기준(시행령 제2조)의 문제이고, 언론중재법은 미적용이나 정보통신망법 제44조의2(삭제요청)는 등록 여부와 무관하게 이미 적용 중이다. 네이버 뉴스제휴·구글 뉴스 Publisher Center 둘 다 "신청·승인" 관문이 사실상 없거나(구글, 자동판단) 등록증을 요구해(네이버) 선택지 밖이다.
- 소재 확보(§2)가 화면 구조(§3)보다 우선한다는 점을 GA4·GSC·네이버 데이터 상관관계로 뒷받침했고, 기획자 07 수집기는 실측 산출량이 낮아 지금은 재가동을 권고하지 않았다.

## 주요 결정사항 (자체 판단 + 근거)
1. **"언론사"·"기자" 표현을 피할 것을 권고** — 신문법이 직접 금지하는 조항은 없지만(확인함, check-log §1), 법정 용어(언론중재법 제2조12호)와의 오인 리스크가 크다는 자체 판단. 강제 조항이 아니라 편집 정책 권고로 남겼다.
2. **`BackgroundNewsArticle` 서브타입 제안** — 기존 프로그래머 결정(Article 채택, `src/lib/seo.ts` 주석)의 우려("NewsArticle=자체취재 오인")를 스키마 수준에서 해소할 수 있다고 판단했다. 최종 적용은 사용자·프로그래머 확인 필요로 남겼다(D3).
3. **자동 수집기(기획자 07) 재가동 보류** — 리뷰 15의 실측 수치(연합뉴스 외 전부 매칭 0건)를 근거로, 투자 대비 산출이 낮다고 판단해 "지금은 하지 않는다"를 권고로 제시했다. 결정 자체는 U3~U5(기존 리뷰 15 승계)에 걸려 있어 사용자 결정 필요 목록에 그대로 남겼다.
4. **카테고리 필드 신설 없이 태그 진열만 변경** — PRD §4.2 유보를 뒤집을 근거(사용자 지시)가 이번 오더에 없어, 스키마 변경 없는 "진열 방식"만 제안했다.

  - 🔴 **08-1에서 정정(리뷰 20 P1-2)**: 위 "법정 의무" 표현은 틀렸다. 정보통신망법 **§2①3호**(08-3 수정, R-P3-5 — 종전 "§44의2①3호"는 조문 번호 오기. 영리 요건은 §44의2가 아니라 §2①3호 "정보통신서비스 제공자" 정의에 있다)의 "영리를 목적으로" 요건 충족 여부가 확인 필요라, §44의2 적용 자체가 확인 필요다. D2는 "자율 절차로 명시 — 적용되는 경우 ⑤ 약관 명시 요건도 함께 충족"으로 다시 쓴다. 상세는 `planning/news-format-conversion.md` §1.3·D2 참조.
