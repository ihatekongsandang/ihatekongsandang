## 주요 결정사항 (자체 판단 + 근거)
1. **페르소나·USP 미작성** — 소재·톤이 미정인 상태에서 구체 페르소나를 서술하면 추측이 되므로, §2를 "질문 목록 + 미확정 시 골조 수준 유지" 방식으로 대체. (근거: CLAUDE.md 대전제 "추측 금지")
2. **안정 ID 원칙을 §3.1에 🔴로 명시** — v0.4~v0.6이 이 값을 외래키로 쓰므로 프로그래머가 스키마 확정 시 반드시 인지해야 함을 강조.
3. **디바이스 대응 방식(반응형) 제안** — v0.1이 지도-리스트 같은 구조적 분기가 없는 단순 카드 피드이므로 적응형보다 반응형이 유지비 효율적이라 판단. 사용자 확정 대기.
4. **피드 방식(무한스크롤+더보기 하이브리드) 제안** — 순수 무한스크롤의 SEO/공유 URL 단점을 보완하는 절충안으로 제시. 사용자 확정 대기.
5. **v0.3 제보 동의 필드를 v0.1 스키마 설계 시점부터 고려하도록 명시** — 소급 추가 리스크를 피하기 위함.

## 미해결·이슈 (다음 세션이 알아야 할 것)
- `planning/user-questions.md`의 1~5번(소재·톤·독자·운영자 노출 여부)이 답변되기 전까지는 카테고리 체계·상세 페르소나·KPI 소재 특화 지표를 구체화할 수 없음. 다음 기획 오더는 이 답변을 전제로 진행 필요.
- §4.2 카테고리 체계는 현재 "설계 원칙"만 제시, 실제 카테고리명은 없음 — 프로그래머가 콘텐츠 스키마 확정 시 카테고리 필드를 자유 텍스트/enum 중 무엇으로 할지 판단 시 이 점 참고.
- 리뷰어(Fable 5.1) 검증 시 중점 확인 필요: (1) 정책 충돌 여부(§5 저작권 정책과 §6 제보 정책 간 정합성) (2) 우선순위 누락 여부 (3) 사용자 요청 누락 여부 — 특히 로드맵 6단계 순서가 원문 지시와 정확히 일치하는지.
