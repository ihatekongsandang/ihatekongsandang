## `useSourceImage` 기본값 처리
지시대로 §3.2①에 **"기본값: 리뷰어 04 판정 대기"**로만 표기했다. `content/README.md`를 읽어 확인한 결과 현재 코드는 `false`를 기본값으로 구현했고, PRD v0.3까지는 `true`를 제안했었다 — 이 차이가 리뷰어 04가 판정할 대상이다. 값을 임의로 정하지 않았다.

## 주요 결정사항 (자체 판단 + 근거)

**M2 택일: 5종 유지 + `기소` 정의 확장 + 배지 병기** (6번째 `무죄판결` 라벨 대신)
- 근거 ①: `유죄판결`이 이미 "라벨=절차 단계, 병기=심급"의 구조이므로, `기소`에 "직전 판결 결과" 선택 병기를 추가하는 것이 대칭적이고 문서 일관성이 높다.
- 근거 ②: 6번째 라벨을 신설하면 enum이 6종으로 늘어나 리뷰어 02 §7 항목1의 "5종 기본값" 전제에서 더 멀어진다. `content/README.md`를 읽어 확인한 결과 코드가 이미 5종 enum과 빌드 검증("`status`가 5종 밖의 값 → 빌드 중단")을 구현해 두었으므로, 6종으로 늘리면 그 검증 로직 자체를 다시 짜야 하는 재작업이 발생한다(리뷰어 02 §7 우선 원칙의 취지 — 불필요한 재작업 회피 — 와 부합).
- 근거 ③: 리뷰어 02 N3가 요구한 "카드 배지 한 단어로 기소≠유죄판결 구분"은 5종만으로 이미 충족되고, 병기는 이를 보강할 뿐 필수 요건은 아니다.
- 이 결정은 코드를 **수정하지 않고 읽기만** 한 상태에서 PRD 문서 안에서 내린 판단이다. 리뷰어 04·05가 코드와 대조해 이 결정을 재검토할 수 있다.

**M4 발견 사항**: 대표 이미지 필수/선택 여부는 03에서 "§7 15항목 불일치 0건"이라고 보고했으나, 그 대조는 §7의 "선택" 목록과 §3.3 빌드 검증 문장 자체를 직접 비교하지 않아 놓친 것이었다(리뷰어 03이 정확히 짚음). 이번에 `content/README.md`를 직접 읽어 실제 구현이 이미 "선택" 쪽으로 되어 있음을 확인했으므로, PRD만 고치면 되고 코드·§7 사이의 추가 불일치는 없다.

## 미해결·이슈 (다음 세션이 알아야 할 것)
- `useSourceImage` 기본값(`true` vs `false`)은 리뷰어 04 판정 대기 — 판정 후 기획자 05 또는 슈퍼바이저가 PRD에 확정값을 반영해야 한다.
- `종결` 사유 하위 필드(가칭 `closureReason`)는 이번에 PRD에 **신설**한 요구사항이다. `content/README.md`를 읽어보니 현재 코드는 종결 사유를 별도 필수 필드가 아니라 "본문이나 `statusHistory`의 `note`에 적는다"는 자유 형식으로 구현해 두었다 — **PRD(M3, 이번 반영)와 현재 코드 구현 사이에 차이가 있다.** 코드를 수정하지 않았으므로 이 차이를 그대로 남겨 리뷰어 04·슈퍼바이저에게 알린다. 리뷰어 02 §7 우선 원칙에 따르면 이런 경우 §7(및 그 이후 코드)이 우선하지만, M3는 §7 항목이 아니라 리뷰어 03이 이번에 새로 요구한 사항이므로 우선순위가 자동으로 정해지지 않는다 — 슈퍼바이저가 판단해 줄 것을 요청한다.
- AI기본법 제31조② 적용 여부(Q2)는 법률 자문이 필요한 확인 필요 사항으로 남아 있다.
