## 1. 확인 필요 — 정확한 390px·1280px 뷰포트

- `resize_window` 도구가 이 세션에서도 **완전히 무반응**이었다(390/800/1920 어떤 값을 넣어도 탭의 실제 `window.innerWidth` 불변) — 디자이너 01·테스터 01과 동일 결함 재현.
- 이번 세션에서 추가로 **iframe으로 390px 컨텍스트를 직접 만드는 방법**을 시도했으나, 배포본이 `x-frame-options: DENY`를 보내 **자기 자신도 프레이밍을 거부**해 실패했다(사이트의 의도된 보안 설정이라 우회하지 않음).
- 대신 세션에서 실제로 관찰 가능했던 고정폭 중 **모바일 대역 599px**, **데스크톱 1920px**로 전 항목을 실측했다. `TagNav`는 Tailwind 브레이크포인트가 아니라 `flex flex-wrap`으로 컨테이너 실폭에 반응하는 구조(`src/components/tag-nav.tsx` 확인)라 599px·1920px 실측도 유효하지만, **리뷰어 재현값(390px 기준 nav 130px·카드 top 638~658px)과는 폭이 달라 직접 비교는 할 수 없다.**
- 원본 로그·재현 절차: `docs/tools/tester-02/measure-log.md` §1.

## 6. 확인 필요 — 실제 VoiceOver 음성·iOS Safari 실기기

claude-in-chrome에는 음성을 실제로 재생·청취하는 기능이 없다(테스터 01·디자이너 01과 동일 한계). §5의 접근성 트리·DOM 속성 확인으로 "VoiceOver가 그렇게 안내할 조건은 갖췄다"까지만 간접 확인했고, 실제 음성 문구·순서는 **확인 필요**로 남긴다. iOS Safari 실기기 검증도 이 환경에 없어 **확인 필요**.
