# 게시물 작성 가이드 (`content/posts/`)

이 문서 하나만 보고 게시물을 쓸 수 있게 만든 문서다. 게시는 **파일을 만들고 커밋하면 끝**이고,
관리자 화면이나 DB는 없다. 대신 커밋 전에 **검증 스크립트가 게이트 역할**을 한다.

```bash
npm run validate:content   # 검사만
npm run build              # 검사 통과해야 빌드가 진행된다(prebuild에 물려 있음)
```

검증에서 하나라도 걸리면 빌드가 멈추고, 어느 파일의 어느 필드가 왜 잘못됐는지 한국어로 출력된다.

---

## 1. 3분 요약

1. 이미지가 있으면 `public/images/{id}/` 밑에 넣는다.
2. `content/posts/{id}.md` 파일을 만들고 아래 필드를 채운다.
3. `npm run validate:content` 를 돌려 초록 불을 본다.
4. 커밋·푸시하면 배포된다.

URL 게시물은 1~2번을 대신 해주는 초안 생성기가 있다.

```bash
npm run --silent og:draft -- https://example.com/article > content/posts/my-post-id.md
```

> ⚠️ `--silent`를 빼면 npm이 찍는 `> ihatekongsandang@0.1.0 og:draft` 배너까지 파일에 들어가
> frontmatter가 깨진다(첫 줄이 `---`가 아니게 되어 검증이 "id 필수입니다"부터 쏟아낸다).
> `node scripts/og-draft.mjs <URL> > 파일` 로 직접 실행해도 된다.

원문의 OG 메타(제목·요약·썸네일·사이트명)를 읽어 frontmatter 초안을 만들어 준다.
추출에 실패해도 멈추지 않고 빈 필드로 초안만 만들어 주므로 손으로 채우면 된다.

**사람이 판단해야 하는 것은 일부러 비워서 내보낸다** — 비어 있으면 빌드가 막힌다.

| 비워서 나오는 것 | 왜 |
|---|---|
| `title` · `description` | 원문 헤드라인을 그대로 옮기면 카드 제목·h1·`<title>`이 원문과 글자 그대로 같아지는데, 그 자리에는 "출처 인용" 표시가 없어 **운영자가 단정한 문장처럼 읽힌다.** §5의 인용형으로 직접 쓴다 |
| `status` | 사실 확인 단계는 기계가 알 수 없다 |
| `sources[].type` | 그 매체가 §3.2의 허용 출처에 드는지는 사람이 확인해야 한다. 출처의 `name`·`url`·`date`는 기계가 아는 값이라 채워서 나온다 |

`useSourceImage`는 `false`로 나온다. 원문 썸네일을 카드에 쓰려면 `og.image` 주소를 브라우저로
직접 열어 보고 인물의 얼굴이 식별되지 않을 때만 `true`로 켠다(§3.4).

원문 제목·요약은 `og.title`·`og.description`에 **그대로 보존**되고, 상세 페이지에
"원문 제목(출처 인용)"·"원문 요약(출처 인용)"으로 표시된다. 그쪽은 고치지 않는다.

## 2. 파일 형식

```markdown
---
(여기가 frontmatter — YAML)
---

(여기가 본문 — 마크다운. 유형에 따라 없어도 된다.)
```

본문에 HTML을 직접 쓸 수 없다. 렌더링 단계에서 전부 제거되고, `<script>`·`<iframe>` 류는
검증에서 오류로 막힌다.

🔴 **본문에 이미지를 넣지 않는다.** 마크다운 이미지(`![설명](주소)`)는 렌더에서 제거되어 화면에
나오지 않는다. 사진은 반드시 frontmatter `images[]`로 넣는다 — `alt` 필수 검증, 원문 썸네일
사용 여부(`useSourceImage`) 판단, 이미지가 깨졌을 때 대체 이미지로 바꾸는 처리가 전부 그쪽에만
걸려 있기 때문이다. 본문에 마크다운 이미지를 쓰면 검증이 경고로 알려 준다.

## 3. 필드 표

### 3.1 모든 유형 공통

| 필드 | 필수 | 형식 | 설명 |
|---|---|---|---|
| `id` | ✅ | 소문자 영숫자 + 하이픈 | **한 번 정하면 절대 바꾸지 않는다.** `/post/{id}` 주소가 되고, 나중에 좋아요·공유수·댓글이 이 값을 키로 쓴다. 파일명에서 자동으로 만들지 않으므로 직접 적는다 |
| `title` | ✅ | 문자열 | 카드·상세·검색 결과 제목 |
| `description` | ✅ | 문자열 | 1~2문장 요약. meta description과 AI 인용에 쓰인다. 160자를 넘으면 경고(오류는 아님) |
| `publishedAt` | ✅ | `YYYY-MM-DD` | 피드 정렬 기준(최신순) |
| `updatedAt` | | `YYYY-MM-DD` | 내용·라벨을 고친 날 |
| `status` | ✅ | 아래 5종 중 하나 | 사실 확인 단계. 카드 배지로 나간다 |
| `courtLevel` | 조건부 | `1심` / `2심` / `확정` | `status: 유죄판결`일 때만 쓰며, 그때는 **필수**. 다른 상태에 쓰면 오류 |
| `sourceType` | ✅ | `url` / `photo` / `photo_text` | 게시물 유형. 화면 구성이 갈린다 |
| `attribution` | ✅ | 문자열 | 출처 표기. URL 유형은 원문 매체명, 사진 유형은 촬영자·제공처 |
| `sources` | ✅ | 배열, **최소 1건** | 상태 라벨의 근거. 아래 3.2 참조 |
| `tags` | | 문자열 배열 | 한글·소문자 영숫자·하이픈. v0.1에 카테고리는 없고 태그만 쓴다 |
| `statusHistory` | | 배열 | 라벨을 바꿀 때마다 한 줄씩 쌓는다. 아래 3.3 참조 |
| `submittedBy` | | 문자열 | 제보로 들어온 건을 표시할 때(v0.3 대비) |
| `image` | | `{src, alt, caption}` | 대표 이미지를 따로 지정하고 싶을 때. 없으면 유형별 규칙으로 정해진다 |

### 3.2 `sources[]` — 근거 출처 (필수, 최소 1건)

```yaml
sources:
  - type: 언론          # 언론 | 수사기관 | 법원 | 기타
    name: "매체명 — 기사 제목"
    url: "https://..."
    date: 2026-09-17
```

**출처 없이 올릴 수 있는 게시물은 없다.** 허용 출처는 다음과 같다.

- **언론**: 「신문 등의 진흥에 관한 법률」 제9조에 따라 시·도지사에 **등록된** 신문·인터넷신문,
  「뉴스통신진흥에 관한 법률」상 뉴스통신사, 「방송법」상 방송사업자.
  등록 여부는 문화체육관광부 정기간행물 등록관리시스템(`https://pds.mcst.go.kr/pds/`)에서 확인한다.
  **미등록 매체·1인 미디어·유튜브는 `의혹` 근거로도 쓸 수 없다.**
- **수사기관**: 검찰·경찰·국가정보원 등의 공식 발표·보도자료
- **법원**: 공개된 판결문
- **기타**: 위에 해당하지 않지만 공적으로 확인 가능한 자료

단체·개인의 SNS 글이나 성명서를 **직접** 근거로 삼지 않는다. 그 주장이 위 언론 보도를 통해
인용된 경우에만 `의혹` 근거가 된다.

### 3.3 `statusHistory[]` — 상태 갱신 이력

사건이 진행되면 **새 게시물을 만들지 않고 같은 게시물의 `status`를 고친다.** 그때 이력을 한 줄 남긴다.

```yaml
status: 기소                     # 현재 상태
statusHistory:
  - date: 2026-08-01
    from: 의혹
    to: 수사중
    note: 수사 개시가 발표된 것으로 보도됨
    sourceUrl: "https://..."     # 선택
  - date: 2026-08-20
    from: 수사중
    to: 기소
    note: 공소 제기가 발표된 것으로 보도됨
```

⚠️ **이력의 마지막 `to`는 현재 `status`와 같아야 한다.** 다르면 검증에서 막힌다
(라벨만 바꾸고 이력 추가를 잊는 사고를 막기 위한 장치다).

### 3.4 `sourceType: url` 추가 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| `sourceUrl` | ✅ | 원문 기사 주소 |
| `useSourceImage` | | 원문 썸네일을 카드 미리보기로 쓸지 여부. **기본값 `false`** |
| `og.title` | | 원문 제목(자동 추출값). 상세에 "원문 제목(출처 인용)"으로 그대로 보여준다 |
| `og.description` | | 원문 요약(자동 추출값) |
| `og.image` | | 원문 썸네일 URL(https). `useSourceImage: true`로 두려면 이 값이 있어야 한다 |
| `og.siteName` | | 원문 사이트명 |
| `titleOverride` | | 제목을 직접 쓸 때. 있으면 이 값이 화면에 나간다 |
| `descriptionOverride` | | 요약을 직접 쓸 때. 있으면 이 값이 화면에 나간다 |

원문 썸네일은 **복사해 오지 않고 원 주소를 그대로 참조**한다. 원 사이트에서 이미지를 지우거나
주소가 바뀌면 화면에서 자동으로 대체 이미지로 바뀐다.

🔴 **`useSourceImage` 판단 기준**: 인물의 얼굴이 식별되는 썸네일은 쓰지 않는다(`false`로 둔다).
`기소` 이전 단계(`의혹`·`수사중`)는 특히 그렇다. 판단이 애매하면 `false`가 안전한 쪽이다.

### 3.5 `sourceType: photo` / `photo_text` 추가 필드

```yaml
images:
  - src: /images/my-post-id/scene-01.png   # public/ 아래 실제 파일이 있어야 한다
    alt: "이미지를 설명하는 문장"             # 🔴 필수. 없으면 빌드가 막힌다
    caption: "사진 설명(선택)"
```

- 이미지 **1장 이상 필수**, 이미지마다 `alt` **필수**(WCAG 2.2 AA 1.1.1).
- `alt`는 "사진", "이미지" 같은 말 대신 **무엇이 보이는지**를 쓴다.
- `photo_text`는 frontmatter 아래 **마크다운 본문이 반드시 있어야** 한다.
- 이미지가 여러 장이면 상세 페이지에서 가로로 넘겨 보는 형태로 나온다.

## 4. 상태 라벨 5종

| 라벨 | 언제 쓰는가 |
|---|---|
| `의혹` | 언론 보도, 국회·시민단체 등의 주장·제보에 근거하며 아직 공적으로 확인되지 않은 단계 |
| `수사중` | 수사기관의 수사 개시·압수수색 등 공식 조치가 보도된 단계. 기소 전 |
| `기소` | 검사의 공소 제기가 보도·발표된 단계. 재판 중을 포함한다 |
| `유죄판결` | 유죄 판결이 보도되었거나 판결문으로 확인된 단계. `courtLevel` 필수 |
| `종결` | 무혐의·불기소·무죄·공소기각·공소취소 등으로 종결된 단계 |

🔴 **기소에 "확정"을 붙이지 않는다.** 기소는 검사의 공소 제기이지 유죄 판단이 아니고,
헌법 제27조④·형사소송법 제275조의2가 유죄 판결 확정 전까지 무죄 추정을 정하고 있다.

🔴 **무혐의로 끝난 사건은 게시물을 지우지 않고 `종결`로 바꾼다.** 지워 버리면 혐의가 해소된
사실 자체가 남지 않는다. 종결 사유(무혐의·무죄 등)는 본문이나 `statusHistory`의 `note`에 적는다.

## 5. 제목·요약을 직접 쓸 때 지켜야 하는 것

단정하지 않고 **인용 형태**를 유지한다.

| ❌ 쓰지 않는다 | ✅ 이렇게 쓴다 |
|---|---|
| "…가 간첩이다" | "…라는 의혹이 제기됨" |
| "…한 것으로 밝혀졌다" | "…한 것으로 보도됨" |
| "간첩 ㄱ씨, …" | "…혐의로 기소됨(출처: ○○)" |

실명 표기는 이렇게 나눈다.

> ⚠️ **아래 실명 규칙은 PRD v0.3 기준으로 쓴 것이고, 기획에서 개정이 진행 중이다.**
> 실제 적용 기준은 항상 `planning/prd.md` **§6③의 최신본**을 본다. 개정이 확정되면
> 이 절과 §3.4·§4를 함께 갱신한다(프로그래머 03 이월 과제).

- `의혹`·`수사중` 단계 인물은 **운영자가 직접 쓰는 문구**에서 실명 대신 이니셜("ㄱ씨")을 쓴다.
- 다만 **자동 추출한 원문 제목·요약(`og.title`, `og.description`)은 고치지 않는다.** 그것은
  원문 그대로의 인용이고, 화면에 "원문 제목(출처 인용)"이라고 표시된다.
- 선출직·고위 공직자 등 **언론이 이미 실명으로 보도한 공인**은 언론 표기를 따른다.
- `유죄판결` 단계 인물은 실명 표기가 가능하다. 미성년자 등은 예외로 비공개를 유지한다.

## 6. 게시물을 내릴 때

파일만 지우면 안 된다. **`content/retired-ids.txt`에 그 `id`를 한 줄 추가한다.**
이후 누가 같은 `id`를 다시 쓰면 검증이 막는다(과거 반응·댓글 데이터가 엉뚱한 게시물에 붙는 사고 방지).

정정·삭제 요청이 들어오면 원 출처를 다시 확인한 뒤 **상태 라벨 갱신 → 내용 수정 → 비공개** 순으로
가벼운 조치부터 고른다. 1차 답변은 영업일 3일 이내, 실제 조치는 확인 후 즉시가 이 사이트의 기준이다.

## 7. 완성 예시 3종

### ① URL 게시물

```markdown
---
id: example-case-a
title: "예시 사건 A — 반도체 공정 자료 유출 의혹으로 기소된 것으로 보도됨"
description: "가상의 예시 게시물입니다. 예시신문이 예시 사건 A의 피고인이 공정 자료 유출 혐의로 기소되었다고 보도한 내용을 정리했습니다."
publishedAt: 2026-09-18
status: 기소
sourceType: url
attribution: 예시신문
sources:
  - type: 언론
    name: "예시신문 — 예시 사건 A 공소 제기 보도"
    url: "https://example.com/press/example-case-a"
    date: 2026-09-17
tags:
  - 예시사건
  - 기술유출
sourceUrl: "https://example.com/press/example-case-a"
useSourceImage: false
og:
  title: "예시 사건 A 피고인, 공정 자료 유출 혐의로 기소"
  description: "예시신문 보도(가상). …"
  siteName: 예시신문
---

본문은 없어도 된다. 운영자 메모를 남기고 싶을 때만 쓴다.
```

### ② 사진 게시물

```markdown
---
id: example-case-b
title: "예시 사건 B — 연구시설 출입 기록 관련 의혹이 제기됨"
description: "…"
publishedAt: 2026-09-19
status: 의혹
sourceType: photo
attribution: "직접 촬영"
sources:
  - type: 언론
    name: "예시일보 — 예시 사건 B 의혹 제기 보도"
    url: "https://example.com/press/example-case-b"
    date: 2026-09-19
tags:
  - 예시사건
images:

    alt: "회색과 파란색 대각선 띠가 겹친 추상 패턴"
```
